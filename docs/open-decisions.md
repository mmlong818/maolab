## D1 · worked-example LLM 成本（路线图 §7 问题 4）

**背景**：B 阶段为每个程序/概念型知识点生成"完整范例 → 半范例 → 独立题"三档梯度，token 消耗约为当前 2-3 倍。

| 选项 | 成本 | 教学效果 | 风险 |
|---|---|---|---|
| **A. 全量三档** | 2.5x | 最佳 | 成本爆炸；新课程生成慢 |
| **B. 按知识点重要度分级**（核心概念三档、次要一档） | 1.5x | 良好 | 需要"重要度"打分机制 |
| **C. 缓存复用**（同 knowledgeType 同难度共享 worked-example） | 1.2x | 中等 | 缺乏个性化；同类题面孔重复 |
| **D. 学生触发式生成**（首次 worked-example 完整生成，半范例和独立题按需生成） | 1.3x | 良好 | 实时生成延迟；缓存命中率取决于活跃度 |

**推荐：B + D 组合**——核心概念预生成完整三档（保证质量），次要知识点走触发式按需生成（控成本）。重要度由教材本体的 `objective.weight` 字段决定（金标准延伸）。

**决策需要的信息**：当前单课程平均 LLM 成本 / 用户接受的成本上浮上限。

## D2 · 三阶段节奏（路线图 §7 问题 5）

| 选项 | 时长 | 风险 | 收益时机 |
|---|---|---|---|
| **A. 严格串行 A→B→C** | 8-10 周 | 低 | 第 4 周用户能感知 A 的变化 |
| **B. A+B 并行** | 6 周 | 高（B 依赖 A1 的 knowledgeType 绑定） | 第 6 周一次性大变 |
| **C. A 完成 → B/C 并行** | 7 周 | 中（B 和 C 数据有依赖：B 的 reflection 喂 C 的 retrieval） | 第 5 周中 |

**推荐：C**——A 是地基不能跳，但 B 和 C 的依赖弱（B2 reflection 数据可后补给 C），并行节省 1-2 周。

## D3 · 元认知 atom 的年龄差异化（路线图 §7 问题 3）

**背景**：课尾反思 60 秒对低龄学生可能过长。

|---|---|---|
| **A. 统一 60 秒** | 0 | 低龄不耐烦、走过场 |
| **B. 按学段分档**（小学 30s / 初中 60s / 高中 90s） | 低 | 良好 |
| **C. 按 persona 适配**（猫叔讲述风格慢、配年长稳锚同学；低龄配跳跃同学） | 中 | 最佳，但复杂 |

**推荐：B**——分档简单可控；持有的 grade 字段已能驱动。C 留作 v2 优化。

## D4 · 教材未覆盖 knowledgeType 时的兜底

**背景**：教材是金标准，但 302 本教材里部分章节可能没标注 knowledgeType。

| 选项 | 准确率 | 工程成本 |
|---|---|---|
| **A. LLM 兜底分类** | 中（70-85%） | 低 |
| **B. 规则兜底**（基于关键词 / 章节结构） | 中低（60-75%） | 低 |
| **C. 人工标注队列**（未覆盖项进队列，由内容团队补标） | 高 | 中（需要运营接入） |
| **D. A + C 双轨**：LLM 即时兜底用着，同时进人工标注队列 | 高（最终） | 中 |

**推荐：D**——不阻塞产品，逐步把教材本体补齐。

## D6 · 用户自选 persona vs 系统自动调度（persona 库 §7 问题 4）

| 选项 | 用户体验 | 教学质量 |
|---|---|---|
| **A. 全自动**（系统按规则调度） | 简单 | 调度好则佳 |
| **B. 全自选**（用户选老师 + 同学组合） | 自主感强 | 用户可能选不合适的组合 |
| **C. 自动为默认，关键节点允许切换** | 平衡 | 较好 |
| **D. 不同"班级"=不同 persona 套餐**（学生选一个班级，套餐固定） | 直观 | 套餐设计是关键 |

**推荐：C 起步，D 作为 v2 体验升级**。完全自动会让用户感觉"系统在替我做选择"，丧失 Deci 自主感；完全自选门槛太高。

## D7 · 旧课程数据迁移

**背景**：阶段 A1 改了 teachingMode 决定规则，已生成的旧课程是否需要重生成？

| 选项 | 工程成本 | 用户感受 |
|---|---|---|
| **A. 旧课程不动，新课程走新规则** | 0 | 旧/新课体验割裂 |
| **B. 旧课程批量重新生成** | 高（LLM 成本） | 一致体验 |
| **C. 旧课程标记"传统版"，用户可选择重生成** | 中 | 用户主导 |

**推荐：A 起步**——maolab 当前用户量小，新课走新规则不会造成显著割裂。等 worked-example（B 阶段）上线后再评估是否做批量。
