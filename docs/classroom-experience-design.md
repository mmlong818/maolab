# maolab 课堂体验设计 v1

> 2026-06-10 · 起因：流水线（教材/KP/学情）已及格，但课堂体验层"勉强及格"——语音没了、同学没了、呈现简单、交互弱、老师个性化浅。
> 方法论：HumanCenteredDesign + NarrativeDesign + BehavioralPsychology（教育设计组合，叙事用于课堂节奏，行为心理用于注意力与动机）。

---

## 0. 稳定核心（不许变的东西）

| 维度 | 内容 |
|---|---|
| 核心身份 | **猫叔的教学研究室**：把真实国家教材变成能直接上的课。不是"AI 聊天学习"，是"一节课"。 |
| 核心体验 | "一位懂教学法的老师**真的在给你上课**"——有声音、有节奏、有注视感。 |
| 核心情绪锚点 | 被一位好老师认真对待的**安全感**；课堂该有的**生气**（不是死寂的翻页）。 |
| 核心世界观 | 教学严肃性：国家教材 KP、Bloom 目标、教学法（socratic/flipped/interactive）、学情闭环。娱乐性服务于教学，不喧宾夺主。 |
| 创作者人格 | 这个项目自己的执念是**剧场隐喻**——节目单（rundown）、分镜、讲稿、演出层（beats）。体验设计应该把这个隐喻推到底，而不是照抄 OpenMAIC 的"圆桌"隐喻。 |

---

## 1. 差距盘点（OpenMAIC vs maolab 现状）

| 维度 | OpenMAIC（参考项目） | maolab 现状 | 差距定级 |
|---|---|---|---|
| 语音授课 | 双轨 TTS：讲课预生成 + 讨论实时队列；语音与动作严格同步（说完才走下一步）；人设绑定音色 | `/api/tts` 完整（DashScope cosyvoice），4 位老师 voiceId 都配好，但**前端零调用** | 🔴 断链（最易修） |
| AI 同学 | 12 个人格智能体 + LangGraph Director 实时编排，同学互相接话、白板写字、可被用户打断 | "🙋 同学选了"= 前端随机选错选项；"同学思考中"= 硬编码 8 秒计时器；4 个学生人设定义完整但**无人使用** | 🔴 只有影子 |
| 教学呈现 | Canvas slide + spotlight/laser 指针 + **活白板**（AI 边说边写，800ms 淡入）+ interactive iframe（物理模拟等） | 9 种 atom 大多是文本卡片；beats 演出层只覆盖 image-caption 1 种；reveal effect 字段定义了但没实现 | 🟡 覆盖面不足 |
| 老师个性化 | persona + 音色 + 头像 + 颜色 + 能力白名单 + 调度优先级，六维生效 | persona 只影响讲稿文案一维；voiceId 躺着没用 | 🟡 一维生效 |
| 课堂流程 | actions[] 乐谱自动播放，讨论是暂停点，可打断、可调速（1x/1.5x/2x） | 手动翻页（箭头键），无自动播放、无节奏控制 | 🔴 无乐谱 |
| **maolab 独有资产** | （无） | **教材 KP 对齐、学情追踪、diagnose-gap 前置查漏、教学法编排、QA 质检、atom 复用、PPT 导出** | 🟢 反超点 |

**一句话**：OpenMAIC 强在课堂的**临场感**，maolab 强在内容的**教学正确性**。体验设计的目标不是抄回临场感，而是让临场感长在教学正确性上。

## 2. 三个方向（结构性差异，非换皮）

### 方向 A ·「广播剧课堂」—— 预生成乐谱，声音优先

**方法论**：NarrativeDesign（课堂=叙事节奏）+ 与现有管线同构

**结构**：把"演出"做成**生成产物**。备课阶段为每个 atom 生成一份"乐谱"（扩展现有 beats）：老师讲解（预生成 TTS，按人设音色）→ 同学插话/错答（**剧本角色**：备课时 LLM 按 atom 和学生人设写好台词，预生成不同音色语音）→ 提问暂停点 → 老师讲评。课堂自动播放，学生可暂停/答题/举手提问（举手时才走实时 LLM）。

- **同学的实现**：不是实时智能体，是**剧本里的角色**——像广播剧。Zero/小陈/段子K/小美（人设已在 teachers.ts）在乐谱里有台词、有声音、有典型错误。
- **结构本质**：课是一场排练好的演出，互动是演出中的有限暂停点。
- **优点**：与现有 pipeline 完全同构（都是备课产物）；成本前置、播放零延迟、质量可 QA、可离线、可导出；声音体验立刻拉满。
- **代价**：互动是"剧本内"的，学生提问之外没有真正的即兴。
- **新颖度**：明显差异化（OpenMAIC 是实时流，这是预生成乐谱——结构相反）。

### 方向 B ·「教研室直播间」—— 实时编排，学情驱动的同学

**方法论**：SystemsThinking（多智能体系统）+ HumanCenteredDesign

**结构**：嫁接 OpenMAIC 的 Director 实时编排（LangGraph：director → agent_generate 循环），老师 + 2-3 个同学实时发言、实时 TTS 队列、可打断。但同学的灵魂换掉：**同学犯的错来自真实学情**——错答由 kp_relations 上游薄弱 KP 的典型误区生成（"小陈又把挥发性和吸水性搞混了"——因为这是 diagnose-gap 统计出的真实高频混淆）。白板=活板书，老师边说边写。

- **结构本质**：课堂是实时演算的多方对话，内容生成发生在播放时。
- **优点**：临场感天花板；同学错误有教学功能（针对性纠偏示范），这是 OpenMAIC 没有的 maolab 独有差异化。
- **代价**：工程量最大（编排框架、实时 TTS 队列、流式状态机）；延迟、成本、质量三重不可控风险；与现有"备课产物"架构异构。
- **新颖度**：对 maolab 大胆；若直接抄圆桌 UI 则跌入模板污染——必须用"教研室/黑板"视觉语言重做。

### 方向 C ·「一对一家教」—— 反方向：不做班级感，做被注视感

**方法论**：BehavioralPsychology + JobsToBeDone（自学场景的真实动机：不是要热闹，是要被关注）

**结构**：押注自学模式。砍掉虚拟班级的喧闹，做**深度注视**：老师语音陪读 + 基于学情的实时插话（"你上次在『溶解度曲线』那道题错了，这页我们慢一点"——数据来自 student_responses + diagnose-gap）；答错时现场开小灶：沿 kp_relations 回溯前置 KP，2 分钟微课补完再回主线。同学只有一个——"**同桌**"：和你一起答题、答错时互相讲题（peer learning 的最小实现）。

- **结构本质**：课堂不是剧场也不是直播间，是**家教的书房**。情绪反直觉方向——所有 AI 课堂都在模拟热闹，这里做安静但被深度关注。
- **优点**：与 maolab 学情/KP 资产咬合最深（这些数据 OpenMAIC 根本没有）；LLM 调用集中在关键时刻，成本可控；差异化最锐利。
- **代价**：对授课（投影）模式帮助小；放弃课堂戏剧性。
- **新颖度**：情绪反直觉方向，异质化最强。

## 3. 评估矩阵

| | A 广播剧 | B 直播间 | C 家教 |
|---|---|---|---|
| 解决"语音没了" | ✅✅ 立刻 | ✅ 但工程长 | ✅ |
| 解决"同学没了" | ✅ 剧本同学 | ✅✅ 真同学 | ⚠️ 只有同桌 |
| 解决"呈现简单" | ✅ 乐谱带 reveal/板书 | ✅✅ 活白板 | ⚠️ 不主攻 |
| 解决"老师个性化" | ✅✅ 音色+台词+节奏 | ✅✅ | ✅ |
| 用上 KP/学情资产 | ⚠️ 少量 | ✅ 同学错误学情驱动 | ✅✅ 灵魂用法 |
| 工程风险 | 低（管线同构） | 高 | 中 |
| 成本结构 | 前置（备课时） | 播放时持续烧 | 关键时刻触发 |
| 与剧场隐喻（创作者人格）契合 | ✅✅ 乐谱=分镜的延伸 | ⚠️ 异构 | ⚠️ 另一种隐喻 |

## 4. 推荐：演进路径而非三选一

三个方向不互斥，存在一条自然的演进线：

```
Phase 1 「开口说话」（A 的地基，1-2 天）
  TTS 播放链路：useNarrationAudio hook → NarrationBubble / 听老师讲这页 / LectureMode 讲稿条全部发声
  按老师人设 voiceId 取音色；预生成缓存（备课时合成存盘，播放零等待）

Phase 2 「广播剧乐谱」（A 主体，1-2 周）
  beats-worker 从 1 种 atom 扩到全部 9 种（reveal effect 实装 + await 超时实装）
  乐谱里写入同学台词：4 个学生人设按 atom 类型插话/错答/追问，各配音色
  自动播放模式 + 调速 + 暂停点；LectureQuestionAuto 的假同学换成剧本同学

Phase 3 「被注视感」（C 融合进自学模式，1 周）
  自学模式：学情插话（上次错的 KP 触发慢讲）+ 答错开小灶（diagnose-gap 现场回溯）
  同桌系统：一个 AI 同桌一起答题、互相讲题

Phase 4 「即兴时刻」（B 的最小可行版，按需）
  只在"举手提问"和"讨论暂停点"接实时 LLM + 实时 TTS 队列
  同学错答模式接入班级学情聚合（多人课堂场景）
  完整 Director 编排仅在验证了 1-3 的留存价值后再投
```

**为什么这样排**：Phase 1 是所有方向的公共地基且一天可见效；Phase 2 与现有管线同构、风险最低、一次性解决"声音+同学+呈现+个性化"四个不满的 80%；Phase 3 用别人没有的学情资产建立差异化；Phase 4 的实时化是成本和复杂度黑洞，留到最后按真实需求投入。

## 5. 反同质化自检

- ❌ 避免：照抄 OpenMAIC 圆桌 UI（模板污染）→ maolab 用自己的剧场/教研室视觉语言
- ❌ 避免：同学=随机插科打诨（AI 平均感）→ 同学的每次犯错必须有教学功能（学情驱动的典型误区）
- ❌ 避免：为了"高级感"全面实时化（无意义复杂化）→ 预生成优先，实时只给即兴时刻
- ✅ 保留偏见：节目单/分镜/乐谱的剧场世界观；教学正确性大于娱乐性

## 6. 人类兼容性检查

- 认知负荷：自动播放+可暂停可调速，学生不被迫操作；同学插话频率需上限（每 atom ≤1 次，避免吵）
- 情绪锚点：老师的声音和口头禅是情绪连续性的载体（龙老师的"这里要注意——"必须有声音版）
- 行为可预测：暂停点、答题、举手三种交互固定位置固定手势
- 文化：中文课堂语境（举手、同桌、开小灶都是本土课堂符号，不用"圆桌讨论"这种西式隐喻）
