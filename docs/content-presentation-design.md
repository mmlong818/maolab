# maolab 教学内容呈现升级设计 v1

> 2026-06-10 · 用户诉求：教学内容的展示方式要**更多样、更美观、更符合教学**。
> 现状：9 种 atom 大多渲染为居中文本卡片（AtomRenderer）/通用 slot 栈（BeatStage），视觉同质、教学表现力弱。
> 方法论：AestheticTheory（视觉系统）+ HumanCenteredDesign（认知负荷）+ Semiotics（视觉符号服务学科语义）。

## 0. 稳定核心

- **一页一语义**不变（现有设计原则，认知负荷的根基）
- **剧场隐喻**不变：呈现器是"舞台布景"，beats 是演出节奏
- **教学正确性 > 装饰性**：每个视觉元素必须有教学功能（指示结构/突出对比/承载过程），禁纯装饰
- 反同质化红线：禁 Dribbble 化卡片堆、禁默认 Tailwind 风、禁千篇一律的居中大字

## 1. 三方向（结构异质）

### A.「学科语义呈现器」——内容结构决定形态

每种 atom 按**教学语义**配专属呈现器，不再共用文本卡片：

| atom | 呈现形态 | 教学功能 |
|---|---|---|
| derivation-step | **黑板推导**：动机便签 → 公式大字居中（手写感字体）→ 依据脚注，三区分层 | 推导的"为什么→是什么→凭什么"结构可见 |
| worked-example | **解题工作单**：题目置顶钉住，步骤卡逐张下落，结论盖"✓"章 | 步骤的序列感+完成感 |
| single-claim | **定音锤页**：超大字论断+衬线强调，support 以"证据"小卡片挂下方 | 论断与证据的主从关系 |
| recap-bullet | **便签墙**：要点写在拟物便签上钉在软木板 | 收束的"钉牢"心理暗示 |
| dialogue-turn | **对话剧场**：左右气泡+角色头像，舞台灯光渐暗背景 | 对话的角色感 |
| image-caption | 现有图+文（保留），加 Ken Burns 缓动 | 视觉焦点引导 |
| demonstration | **过程面板**：图居中+底部步骤进度点+旁白字幕条 | 过程的阶段感 |
| single-question | **答题卡**：题干纸张质感+选项磁贴，提交后翻转显色 | 测验的仪式感 |
| single-example | **案例档案**：档案夹标签页+正文，关键句荧光笔 | 案例的"真实材料"感 |

本质：确定性组件库升级，工程可控，与 beats slot 揭示天然兼容。

### B.「课程视觉主题」——一课一气质

把 PresentMode 已有的 presgen 主题 token 系统反哺到课堂模式：备课时按学科+学段+内容气质选定一套主题（色板/字体/纹理/图形语言），全课贯穿。
- 化学=实验室蓝绿+量杯图形语言；历史=羊皮纸+衬线；数学=方格纸+蓝图线条；语文=宣纸+竖排点缀
- 主题 token: `--stage-bg / --ink / --accent / --paper-texture / --heading-font`
- 本质：生成时决定视觉气质，解决"美观且不千篇一律"。

### C.「活黑板」——内容是被写出来的

借鉴 OpenMAIC 白板：内容入场不是 fade，而是**书写过程**——标题粉笔逐字、公式手写笔顺感（SVG stroke 动画/打字机）、示意图线条生长。与 beats narrate 深度耦合：老师说到哪写到哪。
- 本质：呈现=过程而非结果，最贴"课堂"心智。
- 代价：每类内容要做书写化动画，工程最大；过度使用会拖节奏。

## 2. 评估与推荐

| | A 语义呈现器 | B 视觉主题 | C 活黑板 |
|---|---|---|---|
| 解决"多样" | ✅✅ 9 种形态 | ✅ 课间差异 | ⚠️ 形态单一(都是写) |
| 解决"美观" | ✅ | ✅✅ 成体系 | ✅ |
| 解决"符合教学" | ✅✅ 语义结构可见 | ⚠️ 间接 | ✅✅ 过程感 |
| 工程量 | 中(9 组件) | 小(token+映射) | 大 |
| 与 beats 兼容 | ✅ slot 即区块 | ✅ | 需深度改造 |

**推荐组合**：A 为主干 + B 的主题 token 打底 + C 只取精华（标题/公式的"写出来"入场,不做完整白板）。

## 3. 实施切分

- **P1 主题 token 系统**：`classroom-theme.ts`（按学科映射 token）+ 注入 BeatStage/AtomRenderer 根容器
- **P2 语义呈现器**：重写 BeatStage SlotBlock 按 atom 类型分发到 9 个呈现器（slot 揭示状态仍由 beats 驱动）；AtomRenderer 各 View 同步换装
- **P3 书写感入场**：标题粉笔逐字（CSS steps 打字机+字距抖动）、公式 stroke 入场、便签下落/盖章动效
- **P4 真检回归**：两模式（self/lecture）+ 两学科课程走查

## 4. 反同质化自检

- 每个呈现器结构必须不同（便签墙≠档案夹≠工作单），不是同一卡片换底色
- 主题 token 按学科有真实差异（不是改个主色）
- 动效服务教学节奏（书写=讲解同步），超过 600ms 的纯装饰动画禁止

# 附录 v1.1 · KP 驱动的呈现选择 + 配图方法论（2026-06-10）

## 5. KP 驱动的呈现选择

数据基础：25,332 个 KP 全部带 Bloom 知识维度标注（`annotations.knowledgeType`：conceptual 12331 / procedural 9089 / factual 3207 / metacognitive 705）。

**机制**：beats 生成时，LLM 依据「KP 知识类型 + 本页内容特征」从该类型允许的呈现预设中选择，写入 `atom.presentation`；渲染层按 presentation 优先分发，缺省回落 atom type 映射。

**呈现预设库**（在 8 个基础呈现器上扩充 4 个，结构异质）：

| preset | 知识类型 | 形态 | 教学功能 |
|---|---|---|---|
| concept-anchor 概念锚点卡 | conceptual/factual | 术语大字 → 一句定义 → 生活锚点 三层渐次 | 概念的"名-义-例"结构 |
| comparison-table 对比辨析桌 | conceptual（A vs B 辨析） | 双栏对比 + 底部判别口诀 | 易混概念的并置辨析 |
| cause-chain 因果链 | conceptual（规律/原理） | 节点→箭头→节点 横向链 | 因果/条件关系可见 |
| lab-bench 实验台 | procedural（实验/操作） | 器材条 + 步骤列 + 现象→结论高亮 | 实验的"做-看-得"结构 |

允许映射：
- conceptual → concept-anchor / comparison-table / cause-chain / 定音锤 / 黑板推导
- procedural → lab-bench / 工作单 / 过程面板
- factual → concept-anchor / 档案夹 / 便签墙
- metacognitive → 对话剧场 / 便签墙

## 6. 配图方法论

三类图，角色互斥，触发规则不同：

### 6.1 功能图（functional）— 图就是内容
- 定义：承载教学信息本身——结构示意/过程图解/坐标曲线/流程图
- 触发：demonstration 节点；空间结构、图像分析、过程类 KP
- 生成要求：现代教材插图风、白底/浅底、**标注清晰**（引导线+术语）、科学准确性一票否决、16:9
- prompt 模板后缀：「教材级科学示意图，白色或浅色背景，关键部位带中文标注和引导线，构图干净，无装饰元素」

### 6.2 装饰图（decorative）— 图是气氛
- 定义：情感锚点/好奇心钩子——场景照片感、生活情境
- 触发：仅 hook 角色节点；**每课 ≤ 2 张**；禁止出现在概念讲解/推导/收束页
- 生成要求：风格统一跟随课程主题气质，可摄影感/插画感，不带文字标注
- prompt 模板后缀：「生活化场景，自然光影，有情绪张力，不出现文字和标注」

### 6.3 底图（backdrop）— 图是舞台
- 定义：呈现器的背景纹理与学科水印——**不走 AI 生成**，由主题系统提供
- 实现：classroom-theme 的 stageBg（渐变/方格/纸纹）+ motif 水印（学科图形语言 SVG，右下角低透明度）
- 纪律：水印透明度 ≤ 8%，不与内容争焦点

### 6.4 判定流程（生成时）
```
节点要配图？
├─ 内容本身需要图才讲得清(结构/过程/曲线) → functional
├─ hook 节点且本课装饰图配额未满 → decorative
└─ 其他 → 不配图(底图由主题系统兜底, 不算配额)
```
