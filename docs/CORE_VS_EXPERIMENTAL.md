# maolab 核心 / 实验 / 隔离清单

日期：2026-06-30

本文件是项目重启后的执行边界。它不讨论“旧代码有没有”，只定义“新主线应该依赖什么”。

配套文档：[project-redesign-2026-06-30.md](project-redesign-2026-06-30.md)。

## 1. 分区定义

| 分区 | 含义 | 进入主流程 |
| --- | --- | --- |
| 核心 | 没有它就不能生成一节可上的课 | 是 |
| 支撑 | 服务核心，但不是第一屏主体验 | 受控进入 |
| 实验 | 价值可能成立，但会分散主线 | 否 |
| 隔离 | 已证明污染质量或破坏体验 | 否 |
| 旧只读 | 旧课可查看、必要修 bug，但不承载新方向 | 否 |

判断原则：

- 能直接回答“学生学会什么”才可能进入核心。
- 只提升包装、导出、热闹感、媒体感的能力，默认不进核心。
- 与 `Course / TeachingSkeleton / LearningFragment / Scene / Beat / Quality Gate` 不兼容的能力，只能进实验或隔离。
- 新能力如果失败会破坏正式上课，不能进入主流程。

## 2. 核心区

| 能力 | 说明 | 新主线动作 |
| --- | --- | --- |
| 教材 / KP | 产品地基，定义内容来源和知识边界 | 保留，接入 `Course.sourceMaterial` |
| 教学目标 | 定义本节课到底教什么、不教什么 | 保留，接入 `LessonGoal` |
| TeachingSkeleton | 稳定课程结构，避免 LLM 自由编排 | 保留并升级为必经层 |
| LearningFragment | 学生真正学习的最小单元 | 保留概念，重写为新模型 |
| Scene | 一个教学画面，绑定视觉焦点、板书、讲解锚点、角色层 | 新建 |
| Beat | Scene 内的讲解、显现、提问、等待、反馈节拍 | 新建 |
| StageCanvas | 1920×1080 教学舞台 | 新建 |
| DialogueLayer | 角色对话层，支持半身、头像、旁白、退场 | 新建 |
| SceneTechnique | 展示与交互技术库 | 新建 |
| Quality Gate | 教学、画面、表演、资产、角色音色、展示交互六类闸门 | 新建 |
| 备课工作台 | 老师审目标、骨架、脚本、画面和质量问题 | 新建 / 收拢旧入口 |
| 上课模式 | 唯一正式播放体验 | 统一旧 `LectureMode` 与 beat 播放能力 |
| 个人跟课 | 上课模式里的个人节奏，不是自学模式 | 合并旧 `SelfStudyMode` 的有用能力 |

## 3. 支撑区

| 能力 | 说明 | 规则 |
| --- | --- | --- |
| 课程库 | 课程状态、质量状态、最近真实检查 | 可以保留 |
| TTS 接入 | 支撑老师讲解和角色音色 | 必须绑定 `voiceProfiles` |
| 角色资产 | 老师、同学、旁白立绘和表情 | 必须绑定 `castProfiles` |
| PPTX 导出 | 输出能力，不是主产品体验 | 只能导出通过质量闸门的课程 |
| Insights / 学情 | 支撑个人跟课和补教 | 只能服务学习反馈 |
| Skeleton approve | 骨架沉淀工具 | 作为备课工作台高级能力 |

## 4. 实验区

| 能力 | 原因 | 恢复条件 |
| --- | --- | --- |
| live 多人实时课堂 | 工程复杂，容易抢主线 | 新上课模式稳定后重新评估 |
| media remix | 容易把课变成课后包装 | 只能从通过质量闸门的片段生成 |
| 整课视频导出 | 容易变成 PPT 式视频 | 片段视频真实检查连续通过后再恢复 |
| 复杂 PPT 编辑器 | 会反向牺牲教学节拍 | 仅保留导出，不做编辑器 |
| 多套视觉宇宙 | 维护成本高，容易压过内容 | 先做统一舞台和学科气质变化 |
| 批量生成 10+ 新课 | 当前质量未稳定 | 黄金样板课通过后再开放 |

实验区可以保留代码，但入口必须远离主流程。实验区不能成为默认路径，也不能影响新课生成。

## 5. 隔离区

| 能力 | 隔离原因 | 状态 |
| --- | --- | --- |
| 旧整课视频导出 | 已证明画面和讲解脱节，污染质量判断 | 隔离 |
| 旧 Grounding 修复 | 曾把老师讲解改成机械模板，造成复读机 | 隔离 |
| 黑箱 repair | 把所有问题交给一个接口重写，无法定位根因 | 禁止进入新主线 |
| 平行 Present 体验 | 和正式上课模式形成两套视觉语言 | 降级 / 合并 |
| 旧 SelfStudyMode | 概念错误，自学仍然需要教 | 取消 / 合并 |

隔离区代码如果还存在，只允许为了兼容旧数据或确认删除风险而读取，不允许新功能依赖。

## 6. 旧只读区

| 旧结构 | 新定位 |
| --- | --- |
| rundown | 迁移参考，应被 `compile-lesson` 替代 |
| atoms-only | 迁移参考，应被 `fill-scenes` 替代 |
| script-only | 迁移参考，应成为 `Scene.teacherScript` |
| showscript | 迁移参考，应统一到脚本来源 |
| AtomRenderer | 旧渲染参考，不能作为新舞台标准 |
| PresentMode | 旧放映参考，不能作为平行体验 |
| BeatStage | 有用能力迁移到 `StageCanvas + Beat` |

旧只读区可以修 bug，但不能继续堆新产品判断。

## 7. 新代码准入规则

新增代码进入主线前必须回答：

1. 它服务哪个学习目标？
2. 它属于 `domain / generation / quality / runtime / presentation / adapters` 哪一层？
3. 它是否能映射到 `Course / Scene / Beat / Quality Gate`？
4. 它失败时是否有降级方案？
5. 它是否会让旧模式重新成为默认路径？

答不清的代码默认进入实验区。

## 8. 第一轮交付边界

第一轮只做这些：

- 建立新主线类型入口。
- 建立核心 / 实验 / 隔离清单。
- 建立 StageCanvas / DialogueLayer / SceneTechnique 的 registry 草案。
- 建立六类质量闸门的类型草案。
- 做一节黄金样板课的垂直切片。

第一轮不做：

- 不迁移全部旧课程。
- 不恢复旧自学模式。
- 不恢复 live。
- 不恢复 media remix。
- 不恢复旧整课视频。
- 不批量生成新课。
