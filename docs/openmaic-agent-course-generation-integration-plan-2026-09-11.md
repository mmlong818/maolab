# OpenMAIC Agent 编排融合实施计划

状态：G0、G1、G2、G3、G4 已完成；下一阶段为 G5 整课审计与教师验收

日期：2026-09-11

## 1. 目标

在不削弱 Maolab 现有“投影片先行”内容合同的前提下，引入 OpenMAIC v1.0.1 值得借鉴的生成编排能力，让教师能够：

1. 通过对话补齐课程目标、材料边界和课堂约束；
2. 在生成正文前逐页检查并修改完整投影片计划；
3. 确认计划后逐页生成，每张合格页面立即保存；
4. 中断后从最后一个有效检查点恢复，不重复生成已完成页面；
5. 针对单页提出修改、重绘或重新生成，不重做整门课程；
6. 只有全部页面通过内容、事实、来源、视觉和跨页检查后才能发布。

本计划解决的是“课程生成如何可控、可恢复、可验收”，不是用 Agent 自由文本取代确定性课程规划。

## 2. 必须保持不变

- `LessonPagePlan[]` 仍是页面数量、顺序、目的、问答配对和视觉要求的唯一事实来源。
- 模型只能填写已确认页面的正文、讲稿和受约束视觉描述，无权增删、重排或暗中拆分页面。
- 学生投影片是课堂需要学生看到的全部数字画面；教师讲稿独立保存，不进入学生页面。
- 课堂、备课、缩略图和 PPTX 必须消费同一 `CourseRevision.pages`。
- 问题、作答、揭晓、反馈和分步讲解需要不同阶段时，必须成为不同真实页面。
- 页面标题不低于 36px、正文不低于 28px、图表标签不低于 22px、辅助信息不低于 20px；放不下时退回规划拆页。
- 教材原文、事实和授权资源继续按现有来源合同管理；未经授权的材料不得发送给外部模型。
- 旧课程和当前 `ready` 版本不能因新版本生成失败而被覆盖。

## 3. 不做什么

- 不移植 OpenMAIC 的自由坐标投影片 DSL。
- 不采用“一次提示词生成整门课程”的旧链路。
- 不把聊天记录当成正式课程计划。
- 不把事实核查做成可选按钮或仅供参考的提示。
- 不在展示层根据字数临时增页、删页、换页或缩小字号。
- 不先改造全部历史课程；新链路先服务新建课程和主动创建的新修订版。

## 4. 目标架构

```text
教师输入与授权材料
  -> GenerationSession（持久化 Agent 会话）
  -> SourceBundle（来源、权限、事实边界）
  -> LearningContract（可观察目标与成功证据）
  -> LessonPagePlan[]（确定性完整页序列）
  -> 教师结构化审阅
  -> ApprovedPlanRevision（锁定版本）
  -> PageGenerationJob[]（逐页任务）
  -> PageContent + TeacherCompanion + VisualAsset
  -> 页级阻断门禁
  -> 通过后写入 PageCheckpoint
  -> 整课跨页门禁
  -> TeacherAcceptance
  -> ReadyCourseRevision
  -> 课堂 / 备课 / 缩略图 / PPTX
```

Agent 负责提问、解释、调度工具和组织修改请求；确定性服务负责规划编译、状态转换、版本绑定、门禁和发布资格。

## 5. 核心数据合同

### 5.1 GenerationSession

```ts
interface GenerationSession {
  id: string;
  courseId: string;
  revisionId: string;
  status: GenerationSessionStatus;
  sourceBundleRevisionId: string;
  planRevisionId?: string;
  approvedPlanRevisionId?: string;
  currentPageId?: string;
  createdAt: string;
  updatedAt: string;
  failure?: GenerationFailure;
}

type GenerationSessionStatus =
  | "briefing"
  | "planning"
  | "awaiting-plan-approval"
  | "generating"
  | "awaiting-page-review"
  | "course-audit"
  | "awaiting-teacher-acceptance"
  | "ready"
  | "failed"
  | "cancelled";
```

状态转换只能由服务端命令完成。刷新页面、重复请求或 Agent 重连不得跳过审批和门禁。

### 5.2 结构化页面计划

沿用现有 `LessonPagePlan`，补齐以下不可缺字段或等价字段：

```ts
interface AgentReviewablePagePlan extends LessonPagePlan {
  audience: "student";
  purpose: LessonPagePurpose;
  learningAction: string;
  newInformation: string;
  contentSpec: VisibleContentSpec;
  visualSpec: VisualContract;
  sourceRefs: string[];
  pairRole?: "prompt" | "response" | "reveal" | "feedback";
  pairId?: string;
  teacherCompanion: TeacherCompanion;
}
```

教师审阅界面必须直接编辑这些结构化字段，不允许只保存一段不可审计的 `brief`。

### 5.3 PageGenerationJob

```ts
interface PageGenerationJob {
  id: string;
  sessionId: string;
  pageId: string;
  planRevisionId: string;
  attempt: number;
  status: "queued" | "running" | "blocked" | "passed" | "cancelled";
  inputHash: string;
  outputRevisionId?: string;
  diagnostics: PageDiagnostic[];
}
```

`inputHash` 至少覆盖页面计划、来源事实、授权材料、模型配置和生成规则版本。输入未变化时不得重复计费生成；输入变化后旧检查点不得冒充当前结果。

### 5.4 PageCheckpoint

检查点只能在该页所有阻断门禁通过后写入，包含：

- 页面正文版本；
- 教师讲稿版本；
- 图像或确定性可视化资产版本；
- 来源和事实核查版本；
- 渲染截图与视口信息；
- 字号、裁切、重叠、资源加载结果；
- 生成模型、规则版本和输入哈希；
- 人工修改记录。

## 6. Agent 工具边界

Agent 只能通过明确工具改变项目状态，不能直接拼写数据库对象。

首批工具：

| 工具 | 作用 | 硬限制 |
|---|---|---|
| `read_course_sources` | 读取已授权材料和来源摘要 | 不返回未授权原件 |
| `search_course_sources` | 在当前课程材料内检索 | 返回稳定来源引用 |
| `propose_learning_contract` | 提出学习契约 | 不能直接批准 |
| `compile_page_plan` | 调用确定性规划器 | Agent 不能返回页面数组替代结果 |
| `revise_page_plan` | 结构化修改计划 | 创建新 `planRevisionId` |
| `approve_page_plan` | 锁定计划 | 只能由教师操作触发 |
| `generate_page` | 生成一张既有页面 | 无权改变 ID、顺序、目的和配对 |
| `regenerate_page` | 按教师要求重做单页 | 原检查点保留，可回退 |
| `redraw_page_visual` | 重绘或转入 Cowart 修改 | 不改页面教学合同 |
| `audit_page` | 运行页级门禁 | 失败不得写正式检查点 |
| `audit_course` | 运行整课门禁 | 检查全部当前版本页面 |
| `publish_revision` | 发布当前修订版 | 必须有教师验收且零阻断 |

工具返回必须区分 `validation_error`、`source_error`、`model_error`、`render_error`、`transient_error` 和 `conflict_error`，不能统一显示“生成失败”。

## 7. 重试与恢复规则

- 参数、来源缺失、计划冲突等确定性错误：不自动重试，直接阻断并定位字段。
- 模型格式错误或暂时网络错误：同一输入最多自动重试一次。
- 第二次仍失败：页面标记 `blocked`，保留失败原因，继续生成不依赖该页的任务，但整课不得完成。
- 页面生成成功但门禁失败：不写正式检查点；可以将具体诊断反馈给模型进行一次受约束修正。
- 恢复任务时根据 `inputHash` 和检查点跳过真正完成的页面，不以页面文件“存在”作为完成依据。
- 取消只停止未开始和正在运行的任务，不删除已通过检查点或当前可用课程版本。

## 8. 强制门禁

### 8.1 计划门禁

- 页面 ID、数量、顺序、知识点归属和目标覆盖稳定。
- 一页只承担一个主要认知动作。
- 问题、作答、答案和反馈的先后关系明确。
- 每页说明相对上一页新增了什么。
- 必须看图才能完成的任务已经声明视觉合同。
- 所有知识点均有可观察证据和反馈页面。

### 8.2 内容门禁

- 学生页面不存在教师讲稿、生成理由、内部状态和无作用旁白。
- 问题页面不存在答案、暗示结论或由图像编码泄露的答案。
- 来源页保留必须逐字呈现的原文和出处。
- 页面正文与计划目的、学生动作和配对角色一致。
- 不存在仅换标题或措辞的语义重复页。

### 8.3 事实与来源门禁

- 每条可核查事实都能追溯到当前授权来源或已记录的权威来源。
- 页面正文、讲稿、答案、图像标注之间不存在矛盾。
- 无法确认的事实进入人工确认，不得自动写成确定结论。
- 事实核查版本必须与当前正文版本和计划版本一致。

### 8.4 视觉门禁

- 每一页都在课堂目标画布上真实渲染，不允许抽样代替全页检查。
- 检查投影字号下限、裁切、重叠、横向溢出、无意义留白和资源加载失败。
- 图片尺寸和版面占比由页面任务决定，不使用固定大占位。
- 连续增量页面保持核心元素位置稳定，但仍是独立真实投影片。
- `visualSpec.required=true` 时，没有有效图像或可视化即阻断。

### 8.5 整课门禁

- 课堂、备课、缩略图和 PPTX 的页面 ID、数量、顺序和内容版本一致。
- 学习目标、知识点、典型误区、练习和迁移任务全部覆盖。
- 跨页不存在事实冲突、提前揭底、无来源引用或无意义重复。
- 所有页面均有教师讲稿，且讲稿与当前学生页面一致。
- 任何页面处于 `blocked`、旧版本或未核查状态时禁止发布。

## 9. 教师端流程

### 9.1 对话备课

Agent 只询问会改变课程结果的缺失信息，例如课时、年级、教材范围、学生基础、必须使用的材料和禁止外发边界。已有可靠信息不得重复询问。

### 9.2 计划审阅

按真实课程顺序展示全部投影片计划。每页显示：页号、学生实际看到的内容摘要、学生动作、新增信息、图像要求、来源、与前后页的关系。教师可以增删、重排、拆分和修改；每次修改形成新计划版本。

### 9.3 逐页生成

确认计划后显示真实页序列和进度。页面通过门禁即出现可预览检查点；失败页显示具体原因和可执行修正，其他页面不被整批清空。

### 9.4 单页修改

教师可对当前页发起：修改文字、调整教学目的、重做页面、重绘图片、启动 Cowart 修改。改变教学目的或页面关系必须退回规划；只改变表达和视觉可创建单页内容修订。

### 9.5 整课验收

备课视图只展示教师实际需要的“投影片 + 对应讲稿 + 必要授课提醒”。内部链路、模型解释、诊断详情进入独立质量面板，不混入备课正文。

完成标准：进程中断后可从检查点恢复；重复请求不重复写入或重复计费；错误不会覆盖现有课程。

### G2：教师对话与结构化计划确认

- 新建或改造创建流程，使 Agent 先形成学习契约，再调用确定性规划器。
- 增加完整页序列审阅；支持增删、重排、拆分和修改结构化字段。
- 教师确认产生不可变 `approvedPlanRevisionId`。
- 未确认计划不能生成正文。

完成标准：教师在任何模型调用正文前都能知道整课总页数以及每页学生看到什么、做什么、图像为何存在。

### G3：逐页生成和检查点恢复

- 一次任务只允许生成一张已确认页面。
- 每页生成正文、讲稿和视觉需求后立即执行内容、事实和来源门禁。
- 通过后写检查点；失败保留原因并支持局部重做。
- UI 展示真实页级进度，不显示虚假的整体百分比。

完成标准：任意页面失败不会丢失其他已通过页面；恢复后只补缺页；模型无权改变页面数组。

### G4：全页真实渲染门禁和图像闭环

- 对每一页生成课堂尺寸截图并执行字体、裁切、重叠、资源和留白检查。
- 将现有确定性学科可视化、图像生成、重绘和 Cowart 修改统一绑定到页面修订。
- 图像修改后重新运行页面和跨页事实检查。
- 没有渲染证据的页面不能进入整课验收。

完成标准：测试课程所有页面均有当前版本渲染证据；必需图像缺失、答案泄露和字号不足能够阻断。

### G5：整课核查、教师验收和发布

- 运行目标覆盖、跨页一致性、重复、问答顺序、讲稿一致性和四端同源检查。
- 增加教师整课验收动作与发布签名。
- 只有“机器门禁全通过 + 教师验收”才进入 `ready`。
- 当前 `ready` 版本在新修订版发布前保持可用。

完成标准：课堂、备课、缩略图和 PPTX 全量一致；失败修订版不能污染当前正式课程。

### G6：真实课程试点与生产切换

- 先选择语文、数学、物理三门结构差异明显的真实知识点完成端到端试点。
- 再扩展到十学科，每门至少一节真实课程。
- 每门逐页执行学生视角、教师视角、教育学、视觉设计和产品流程五类人工智能模拟检查，并明确其不等于现实专家签字。
- 通过试点后再将新建课默认入口切换到 Agent 编排链；旧入口保留可回退期。

完成标准：十门课程零发布阻断、零未核查页、零四端版本漂移；代表性高风险页完成真实浏览器操作和截图核对。

## 11. 测试矩阵

必须覆盖：

- 同一输入重复规划得到相同页面结构；
- Agent 尝试增加、删除、重排页面被拒绝；
- 问题页模型返回答案字段被拒绝；
- 教师讲稿或内部说明进入学生正文被拒绝；
- 必需图像缺失、加载失败或与题意矛盾被拒绝；
- 字号低于投影下限、元素重叠或裁切被拒绝；
- 第 N 页失败后前 N-1 页检查点仍有效；
- 服务重启后只恢复未完成页面；
- 修改计划后旧内容、事实和渲染检查点全部失效；
- 只修改图像时不无故重生成正文，但重新执行相关事实和视觉门禁；
- 课程发布过程中存在旧页面版本时整课阻断；
- 课堂、备课、缩略图、PPTX 页数和页面 ID 一致；
- 取消任务不删除已发布课程和已通过检查点；
- 未授权材料不会出现在外部模型请求中。

## 12. 真实验收标准

每个试点课程必须实际完成：

1. 从真实教材知识点创建课程；
2. 在计划阶段逐页检查总页数、学生受众、问答顺序和图像要求；
3. 中途主动停止服务并恢复，验证断点续作；
4. 让至少一页生成失败，验证其他页面不丢失且整课不能假完成；
5. 修改一页文字、重绘一页图片、退回规划拆分一页，分别验证版本边界；
6. 逐页打开备课和课堂页面，检查文字、图像、答案时机和讲稿对应；
7. 导出 PPTX，逐页核对页面与讲稿数量；
8. 检查浏览器控制台、资源请求、数据库一致性和发布状态；
9. 输出课程级报告，列出已验证事实、人工智能模拟评审结论和仍需现实教师判断的风险。

构建通过、接口返回 200 或静态审计全绿，都不能单独视为真实验收完成。

## 13. 发布与回退

- 使用功能开关控制新 Agent 编排入口，默认先对试点课程开启。
- 所有数据库变化先提供迁移、备份和回滚验证。
- 新旧链路并存期间，课程修订版明确记录生成管线版本，不混合消费。
- 切换默认入口前完成干净数据库测试和真实数据只读兼容检查。
- 出现阻断时关闭新入口即可回到原建课流程；不得通过回滚仓库历史恢复数据。

## 14. 风险与决策

| 风险 | 控制方式 |
|---|---|
| Agent 规划看似完整但教学顺序错误 | Agent 只补信息，页面数组由确定性规划器产生并经教师结构化确认 |
| 模型重复调用导致费用失控 | 输入哈希、幂等任务、单次有限重试、页级缓存和明确费用记录 |
| 生成成功但实际页面不可用 | 每页真实渲染后才能写正式检查点 |
| 材料或隐私被外发 | 来源授权清单和外部模型请求审计，未授权默认拒绝 |
| 新修订覆盖可用课程 | 不可变修订版和显式发布动作 |
| 对话文字污染学生页面 | Agent 对话与 `VisibleContentSpec` 完全分离，受众门禁阻断 |
| 局部修复掩盖规划问题 | 修改教学目的、顺序、配对或页数必须退回规划 |
| 自动评审被误认为现实专家验收 | 报告明确标注人工智能模拟，并保留教师验收步骤 |
