# 课程生成与教学视频设计需求总纲

日期：2026-06-29

这份文档用于承接过往真实检查、设计讨论和代码规则。新项目、新线程或新分支启动时，先读这份总纲，再进入具体代码。

## 1. 产品目标

maolab 的目标不是生成一组 PPT，也不是把页面文字念出来，而是把教材知识点变成学生能真正听懂、看懂、参与过的一段课程。

核心体验：

- 像一位懂教学法的老师真的在讲课。
- 内容是主体，声音、角色、画面、配图、视频都服务于内容。
- 学生看到的每一页都能回答：我现在在学什么、老师正在指哪里、为什么这一步成立。
- 课程可以拆成短片段，适合预习、第一次学、复习、测试等不同学习场景自由组合。

不接受的结果：

- 每页只是复读页面文字。
- 老师讲解和画面主体脱节。
- 学生提问没有老师反馈。
- 页面高亮随机变色。
- 配图压缩核心内容，或和教学内容冲突。
- 图示错误、重叠、乱码、无意义。
- 视频里混入系统提示、角色标签、调试文本。

## 2. 课程结构

课程不应只是一条长线，而应由多个不超过 2 分钟的学习片段组成。

推荐片段类型：

| 片段 | 目标 | 推荐形式 |
| --- | --- | --- |
| 预习 | 建立兴趣和问题意识 | 童话、故事、侦探案、生活场景 |
| 第一次学 | 正式建立概念和方法 | 老师讲解 + 现实联系 + 分步图示 |
| 巩固 | 把刚学内容变成可操作步骤 | 例题、纠错、对比、流程卡 |
| 复习 | 快速唤回关键结构 | 口诀、便签墙、知识卡、问答 |
| 测试 | 暴露误区并反馈 | 单题暂停、学生先判断、老师再修正 |
| 拓展 | 换情境迁移 | 案例、项目任务、综合应用 |

基本规则：

- 单个片段最长 2 分钟。
- 每个片段要有明确功能，不要都套“引入 - 讲解 - 提问 - 总结”。
- 同一课程中片段形式要有差异，但差异必须由教学目标决定。
- 已完成片段之间可以自由切换，进行中片段保留状态。

### 2.1 课程颗粒度设计规则

颗粒度的目标不是把内容拆得越细越好，而是让每一个画面都承担真实教学动作。学生翻到任意一页，都应该能说出这一页比上一页新增了什么。

四层颗粒定义：

| 层级 | 职责 | 推荐颗粒 | 硬性边界 |
| --- | --- | --- | --- |
| 课程 | 完成一个清晰学习任务 | 单知识点微课 8-12 个画面；双知识点 12-18 个画面 | 不为“节目效果”扩写外壳 |
| 学习片段 | 完成一个可独立学习的小目标 | 45-90 秒，1-3 个画面 | 代码硬上限 120 秒、5 个画面 |
| 画面 / atom | 承载一个可见教学动作 | 1 个主体 + 1 个新增认知动作 | 不能只有转场、气氛或重复口号 |
| beat | 控制一个画面内部揭示节奏 | 3-6 拍 | 不用 beat 把空讲拖长 |

推荐页序：

- **单一概念或单篇古诗微课**：目标 1 页、情境 1 页、原文/题目 1 页、关键拆解 2-4 页、方法总结 1 页、应用辨析 1-2 页、收束 1 页。
- **程序步骤课**：目标 1 页、完整任务 1 页、关键步骤 3-5 页、易错辨析 1-2 页、完整流程回放 1 页。
- **概念辨析课**：目标 1 页、两个对象同屏 1 页、共同点/差异点 2-4 页、判断规则 1 页、混淆题 1-2 页、收束 1 页。

必须合并的情况：

- 连续两页都在解释同一个词、同一句、同一个动作，只是换一种说法。
- 一页讲“找到了什么”，下一页只把同一批东西重新列一遍。
- 老师需要上一页画面才能讲清这一页，但这一页没有新主体。
- 情境包装页、专家连线页、观众热线页、漫画复盘页没有产生新的教学判断。
- 一个问题拆成“开场页 - 题目页 - 回答页 - 总结页”，但学生实际只做了一次判断。

必须保留或拆开的情况：

- 新画面需要学生观察，例如从池塘画面切到牧童画面。
- 新步骤会改变学生操作，例如从“找意象”转到“抓关键词”。
- 新误区需要学生判断，例如“水草稀少”与“草满水满”冲突。
- 新图示承载不同结构，例如完整原文、局部特写、流程图不能硬塞一页。
- 学生需要先看题目或原文，再听解释。题目、原文、诗句主体必须首屏可见。

浪费页识别：

- 页面只说“我们继续”“准备好了吗”“专家来了”“热线来了”，没有新知识、新证据或新操作。
- 页面有图，但老师没有围绕图上的可见主体讲。
- 页面有台词，但学生看不到台词指向的图、原文、题目或条件。
- 页面重复上一页的定义、口诀、清单，只是换成另一种版式。
- 片段里连续出现 3 个以上“讲解页”而没有观察、判断、操作或反馈。

古诗审美类课程的颗粒模板：

1. **完整原文先出现**：古诗页必须首屏显示完整诗句，不能把诗句藏在后续 reveal 或讲稿里。
2. **意象定义紧贴原文**：定义可以作为旁注，但不能代替原文成为主视觉。
3. **局部画面按“新意象/关键词”拆页**：例如“满”一页，“衔、横、吹”一页；不要为同一个字再拆推导页、追问页、复盘页。
4. **方法只总结一次**：找意象、抓关键词、按空间拼合只需要一页成型，后续直接用题目应用。
5. **辨析题只保留高价值误区**：优先保留能逼学生回到文字证据的题，例如“草稀水少”和“规矩赶路”。

古诗原文页的显示标准：

- 使用 `poem-display` 版式，不使用 `full-bleed-quote` 金句版式。
- 诗题、朝代作者、诗句正文、旁注必须分区显示；诗句正文是主视觉。
- 诗句按原文逐行保留，不能合成一整段，也不能做成背景图里的文字。
- 旁注只解释意象、关键词或朗读提示，不能抢占诗句主体。

生成后颗粒检查单：

- 全课画面数是否符合任务体量，而不是按模板机械扩写。
- 每页是否比上一页新增了主体、证据、操作、判断或反馈。
- 原文、题干、条件、图像主体是否在老师讲解前可见。
- 是否存在连续包装页或连续口号页。
- 是否存在“看图/看插图/图上”但没有真实图像或结构化图示。
- 是否有可以合并成一页的定义、例子、推导、复盘。
- 删掉任意一页后，如果学习链条不受影响，这页默认应删除或合并。

## 3. 老师、学生和对白

课堂不是旁白稿，而是带角色关系的教学场景。

老师必须做到：

- 对学生问题有明确回应。
- 先承接学生表达，再给修正动作。
- 讲到哪里，画面上就必须有对应主体。
- 语言要有角色风格，但不能牺牲准确性。
- 不念系统提示、角色名、导演备注、调试文本。

学生必须做到：

- 不是装饰头像，而是承担课堂功能。
- 可以回答、追问、指出错误、表达困惑。
- 错误必须来自真实学情或典型误区。
- 学生指出错在哪里和为什么错，老师再给修正。

对白节奏：

- 老师提问后必须留停顿。
- 学生可选回答或询问。
- 老师必须反馈：肯定、纠偏、追问或总结。
- 不能出现“学生问了，但老师没有接”的断裂。

角色立绘对白规则：

- 老师、学生不再使用小头像气泡作为主要课堂形象；授课对白使用半身立绘叠加在画面边缘。
- 老师立绘必须按 `selectedTeacherId` 绑定，不能用其他老师资产代替；声音、人设、姓名、立绘必须是同一个老师。
- 每位预设老师必须至少有 `neutral`、`happy`、`thinking`、`surprised` 四种半身立绘表情。
- 讲解节拍的 `emotion` 要驱动立绘表情；旧课没有 `emotion` 时，渲染层按台词语义兜底：平讲用 `neutral`，表扬用 `happy`，纠错/追问用 `thinking`，反直觉/惊讶点用 `surprised`。
- 学段和季节立绘由后台在真实授课入口写入 `castAssetSelection`；季节只按当时上课日期判断一次，前端不得自行按本地时间切换。
- 老师默认站左侧，文字框在右侧；学生默认站右侧，文字框在左侧，形成类似日式 RPG 的对话视线关系。
- 教学舞台按 `1920×1080` 的 16:9 逻辑画布设计；角色、对白、提问和课堂控制都在画面内，不再把对白放到画面外的功能带。
- 默认对白模式是 RPG 半身立绘；当诗句、题干、图像主体或关键证据需要持续展示时，必须降级为 `compact` 头像对白条，必要时继续降级为 `caption` 纯字幕。
- 降级不是资产缺失，而是版式规则：内容主体优先，角色表演服务教学节奏；同一页可随着 reveal 从 RPG 切换到 compact 或 caption。
- 立绘必须优先占用边缘和底部空间，不遮挡诗句、题干、图像主体、关键标注和正在讲解的证据。
- 对白框必须放在教学主体的对侧，不能盖住当前老师讲解的位置。
- 同一页有多轮对白时，角色站位保持稳定；允许文字框的装饰、宽度、留白微调，但不允许每句话都跳位置。
- 没有对应立绘资产时，可以降级为 `caption` 纯字幕版式保护教学内容，但不允许回退到旧头像、错误角色或带背景整图；该课程应记录为资产缺口，后续补齐半身立绘。

## 4. 页面呈现

页面要保持简洁，但不能把上下文拆没。

通用原则：

- 一页一核心语义。
- 重要主体跨页讲解时要保留必要上下文。
- 文字、图示、配图、底纹不得互相遮挡。
- 所有固定格式页面要稳定尺寸，不能因为 hover、反馈、按钮变化导致布局跳动。
- 数学、物理、化学、语文等内容要走学科专用排版，而不是通用卡片。
- 所有教学画面必须有版式骨架：主视觉区、解释区、证据区、互动区各自有位置，不允许把文字简单叠在图上。
- 版式可以固化为模板，但同一课程不能完全长得一样；变化应来自内容类型、画面功能和当前 atom，而不是随机装饰。
- 版式变化必须保持稳定：同一画面内部 reveal 只改变可见性和强调方式，不改变主体尺寸、列宽和关键位置。

页面类型规则：

| 内容类型 | 呈现方式 |
| --- | --- |
| 概念定义 | 概念名、定义、例子、边界分层呈现 |
| 公式 | 公式居中，变量逐一解释，单位必须说明物理意义 |
| 几何推导 | 专用几何图 + 外部推导步骤，不把标签堆在图内 |
| 例题 | 先读题，圈条件和目标，再分步计算 |
| 纠错 | 先让学生指出为什么错，再给修正动作 |
| 古诗审美 | 诗句主体、意象、情绪、表达出口同时保留 |
| 图表读取 | 数据主体、读取步骤、结论分区 |
| 综合任务 | 产出物、标准、知识分工、合成步骤、检查清单 |

## 5. 高亮规则

颜色只能表达教学语义，不能随机装饰。

允许高亮：

- 需要记忆的核心概念。
- 当前正在使用的条件。
- 易错点和错因。
- 修正动作。
- 公式变量和单位。
- 例题中的已知、目标、操作、检查。

不允许高亮：

- 为了好看随便给词上色。
- 同一语义在不同页面颜色不一致。
- 一页高亮过多，导致重点消失。

建议语义色：

| 语义 | 颜色倾向 |
| --- | --- |
| 已知条件 / 概念主体 | 蓝 |
| 结论 / 正确方向 | 绿 |
| 操作步骤 / 推导动作 | 橙 |
| 错误 / 风险 | 红 |
| 审美感受 / 诗句语言 | 紫 |

具体规则已经代码化在 `app/app/lib/v2/*-rules.ts`。

## 6. 图示、配图和底图

必须区分三类视觉资产。

### 6.1 功能图示

功能图示就是教学内容本身，例如几何图、流程图、实验图、公式结构图。

要求：

- 科学、数学和文本内容必须正确。
- 中文必须可读，不乱码。
- 标签不重叠，不遮挡主体。
- 推导步骤尽量放在图外，不塞进图内。
- 对于几何、公式、流程等，优先使用代码绘制或结构化组件，不依赖不稳定生图。

### 6.2 辅助配图

辅助配图用于建立情境和注意力，例如跑步的人、古诗意象、侦探氛围。

要求：

- 必须是生成图像或明确资产，不用 CSS 假装插图。
- 不承载精确信息。
- 不平铺画面，不压缩核心内容。
- 放在角落、侧栏或留白区，低干扰。
- 配图和底纹不能冲突。

### 6.3 封面装饰图

封面要有符合科目和年级气质的装饰配图，但不是具体知识点图示。

要求：

- 同一年级同一学科沿用固定 IP 角色和工具系统。
- 封面建立学科氛围，不提前讲具体课程结论。
- 所谓装饰也必须是真实图像资产。

当前 IP 资产入口：

- `app/app/lib/v2/ip-style-library.ts`
- `app/public/generated-images/cast/base/`
- `app/public/generated-images/cast/subject/`
- `app/public/generated-images/subject-ip/`

## 7. 学科 IP 角色系统

IP 角色不是通用吉祥物，而应按“学科 + 学段 + 年级带 + 内容族”设计。

当前规则：

- 初中数学几何课使用“几何探案员”系列。
- 老师、学生、封面角色来自同一视觉系统；其中老师必须按预设老师 ID 绑定，不能跨老师借图。
- 基础老师卡司包含龙老师、晓梅老师、陈教授、小李老师；每位老师至少有四种表情。
- 问答页可以显示老师造型和学生头像。
- 后续同一年级数学课复用角色与几何工具系统。

扩展规则：

- 不同科目可有不同角色系列。
- 同一科目不同年级可以有不同年龄感和工具系统。
- IP 角色可以随课程前置设计更新，但同一课程内必须统一。

## 8. 教学视频

正式教学视频不是把整课页面截图拼起来。

可用视频必须满足：

- 以片段和讲解节拍为核心。
- 老师语音、学生发言、画面主体一一对应。
- 讲解到细节时，主体不能消失。
- 老师问题后有停顿。
- 学生回答或追问后老师有反馈。
- TTS 输入只包含最终要念的自然语言。
- 不出现“龙老师：”“学生：”“导演提示：”等被念出的标签。
- 视频中可以有页面、圈点、勾画、扩张、局部放大，但不能只是逐页念字。

已隔离的旧整课视频导出见：

- `docs/real-check/QUARANTINED_FLOWS.md`

## 9. 生成质量闸门

课程生成后必须经过质量闸门，不能只看是否能跑。

必须拦截：

- 连续多道选择题。
- 页面重复内容。
- 图示重叠或乱码。
- 文本超出画面。
- 高亮随机。
- 讲解词和画面主体不匹配。
- 连续 reveal 多个要点但老师只讲一句，导致页面像自动播放的提纲。
- 老师讲解只是复读屏幕文字，没有说明观察位置、文字证据和推理关系。
- TTS 混入系统提示。
- 老师无反馈。
- 学生问题无承接。
- 旧流程产物污染新课程。

相关代码入口：

- `app/app/lib/v2/fragment-quality.ts`
- `app/app/lib/v2/fragment-quality-repair.ts`
- `app/app/lib/v2/narration-quality.ts`
- `app/app/lib/v2/atom-composition.ts`
- `app/app/api/v2/present-audit/[courseId]/route.ts`

## 10. 真实检查标准

真实检查不是功能测试，而是真实使用评审。

每轮需要：

- 设定两位互补专家，例如好莱坞导演 + 教育专家。
- 以学习者视角完整走流程。
- 留下真实应用数据。
- 记录观察、疑问和痛点。
- 小问题立即修复。
- 大问题修复后复测。
- 只有颠覆性问题才提交用户决策。

通过标准：

- 学生能听懂。
- 页面能看懂。
- 老师像在教学，不像复读。
- 图示和配图没有误导。
- 片段可以独立学习，也能组合成完整课程。
- 输出视频符合当前课程风格和学习路径。

## 11. 新项目启动检查单

新线程、新分支或新项目启动时，按这个顺序检查：

1. 读取本总纲。
2. 读取 `docs/real-check/QUARANTINED_FLOWS.md`，确认不可用流程不会被调用。
3. 确认课程是否使用片段化结构，并按 2.1 检查画面颗粒是否过碎、过长或重复。
4. 确认学科 IP 是否已有资产，没有则先建立 IP 角色库。
5. 确认页面类型是否走专用呈现器。
6. 确认高亮规则是否来自语义规则。
7. 确认图示、配图、底图角色没有混淆。
8. 确认老师、学生、对白、停顿、反馈完整。
9. 跑类型检查、测试和页面真实检查。
10. 输出视频前先检查 TTS 文本和画面对应关系。
