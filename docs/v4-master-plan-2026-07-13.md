# maolab v4 总方案:有记忆的课堂剧场

日期:2026-07-13
前置:docs/project-redesign-2026-06-30.md(主线宪法,继续有效)、tasks/STRATEGIC-REVIEW-2026-07-ACPF.md(卖点与差距分析)
方法论:SystemsThinking(资产分层与飞轮)为主,NarrativeDesign(剧场季)与 JobsToBeDone(闭环)为辅。

## 0. 一句话结论

v4 不是重启,是在已跑通的主线(教材→骨架→脚本→舞台→反馈)上叠三层新资产:
**教研资产层(隐喻/误概念/事实核查)筑地基,课程季(圣经层)做脸面,学情闭环通最小环。**
版本主题:从「一门一门生成的课」到「一季一季连续、教研背书、认识学生的课堂剧场」。

## 2. 版本主轴:三个候选方向与取舍

三个方向结构真异质(叙事资产 / 教研资产 / 数据回路),不可互相换皮:

### 方向一 · 剧场季(NarrativeDesign 主导)

版本核心 = 圣经层落地:课程从「单课」变成「季」,卡司升格 IP,跨课伏笔与进度状态,学段叙事语气路由。
- 长处:对外最可感知,直接兑现卖点 A/D,建立「追下一课」的留存机制。
- 短处:剧情是内容主体的天然竞争者(重启设计 §4.1 内容优先是宪法);无教研资产护底时,连续性放大错误(错的隐喻讲一季)。

### 方向二 · 教研资产层(SystemsThinking 主导)

版本核心 = 三表资产:隐喻注册表(APPROVED/BANNED + Known_Limits)、误概念库、事实核查闸门(断言分级,FATAL 不放行)。生成质量从「闸门拦截」升级为「白名单供给」。
- 长处:教育产品的生死线;我们的闸门体系已是半成品,扩展成本最低;资产随生产量复利,是真护城河。
- 短处:对外不可感知,单独做一版「用户看不见变化」。

### 方向三 · 学情闭环(JobsToBeDone 主导)

版本核心 = classroom/user-profile 接通 mainline:课中作答→掌握度→下一课生成输入。
- 长处:兑现卖点 C,数据资产起步越早复利越久。
- 短处:依赖连续多课的使用(方向一先行才有连续课);实时自适应会破坏节目单确定性,边界需严格。

### 取舍(拍板项)

**v4 = 方向二筑基 → 方向一点睛 → 方向三通最小环,按此顺序分三个里程碑串行。**
理由:二是一的安全带(隐喻/事实资产先行,剧情连续性才敢放开);一是三的前提(有「季」才有连续学情);三只做课间闭环不做课中实时,保节目单确定性。

## 3. 系统设计(架构增量)

### 3.1 教研资产层 → 新增 `packages/pedagogy`

纯数据 + 纯函数包,与呈现原子库同构(库 + 确定性解析器 + 测试锁定):

- **metaphor-registry**:`{ conceptKey, metaphor, status: APPROVED|BANNED|PENDING, mapping, knownLimits, gradeRange, replacement? }`。
  - fill-scenes 注入:Deep 幕命中注册概念时,只允许使用 APPROVED 隐喻,且**正文必须复述 knownLimits(主动拆穿比喻边界)**;BANNED 条目作为负面约束进 prompt。
  - 未注册的新隐喻不直接否决:标记 PENDING 入人审队列(最小实现 = db 表 + 课程库页一个待审列表)。
- **misconception-registry**:冷启动采用 ACPF 十条经典误概念(机翼等时说 BAN、电流=水流强制限定、拉马克目的论 BAN、乘法变大预防针等),按学科扩充;compile-lesson 为命中 KP 的课强制排入 contrast 幕(误区/修正双卡已有渲染出口)。
- **fact-audit(fill 后新增核查步)**:抽取可判真伪断言 → 分级 FATAL / MISLEADING / IMPRECISE。
  - FATAL → `qualityStatus=blocked`(复用现有机制),**绝不强制放行,两轮修不过转人工**——与现行指图闸门语义一致。
  - MISLEADING → 要求补条件限定;IMPRECISE → 低学段容忍、高学段修正。
- 学段叙事路由:`gradeBand → toneRules`(1-4 禁抽象术语与说教腔 / 5-6 Anti-Cringe 禁词表:「小朋友」「魔法」「神奇之旅」/ 中学禁鸡汤),作为 fill-scenes 生成约束 + 质量闸门禁词检查双保险。

### 3.2 课程季(圣经层)→ db 新增 season 表 + 生成期注入

maolab 已有 Character_Canon(卡司矩阵)与视觉正典(signature 风格包),season 只补「剧情与进度」:

- **schema**:`season { id, subject, gradeBand, castPresetId, stylePackId, seasonTheme, episodeMap, openPlotThreads, progressState }`;课程增加 `seasonId + episodeNo` 可空外键(单课模式不受影响)。
- **注入(compile-lesson 前)**:承接上一课结尾钩子、本课登场角色卡(言行一致,禁 OOC)、当前未回收伏笔;每课结尾生成一条「下集预告」钩子。
- **归档(真检/闸门通过后)**:新增伏笔、角色新事实写回 season,进度状态自动更新;世界观/角色卡变更需人工确认(圣经只增不删)。
- **护栏(宪法条款)**:剧情永远不得抢内容主体——每幕剧情文字预算 ≤ 字幕带一条;剧情只出现在开场承接、幕间过渡、结尾钩子三个位置;去掉剧情后教学必须依然成立(真检检查项)。

### 3.3 学情闭环 → 接通既有包(最小环)

- 环:播放器 quiz 作答 → `packages/user-profile` 掌握度更新 → 课程库页出「复习建议」→ 下一课 compile-lesson 接受 KP 权重输入(薄弱 KP 幕数加权,已有骨架伸缩机制天然支持)。
- 明确不做:课中实时改课(节目单保持确定性);多人同步。
- classroom 包的自适应控制器暂不启用,只取其测验判分与作答记录能力。

### 3.4 技术选型说明

本方案**不引入多 Agent 编排框架**:现有生成管线是确定性 pipeline(compile-lesson → fill-scenes → fill-images 分步 API),fact-audit 与 season 注入都是管线内的普通步骤,无循环/无角色协作/无动态调度,不构成多智能体场景。若未来人审队列要升级为自动化工作流再按选型规则议。

## 4. 里程碑与验收

| 里程碑 | 内容 | 验收(真检驱动) |
|--------|------|----------------|
| M1 教研资产层(~2 周) | pedagogy 包 + 三表冷启动(误概念 10 条起)+ fact-audit 闸门 + 学段语气路由 | round09 真检:事实/隐喻维度零 FATAL;5-6 年级课全文无低幼禁词;contrast 幕命中误概念库 |
| M2 剧场季(~2-3 周) | season schema + 生成期注入/归档 + 结尾钩子 | 同季连续生成 3 课:角色言行一致、伏笔可回收、去剧情教学仍成立;双专家真检「追剧感」 |
| M3 闭环最小环(~2 周) | 作答→掌握度→复习建议→下一课加权 | 一份学生档案跑通两课闭环,薄弱 KP 幕数实际加权 |

每个里程碑收尾跑全量真检;M2 后按 ACPF 落地建议执行「6-8 课连续内容 → 真实孩子测试(追剧意愿 + 一周后留存记忆)」,用数据决定 M3 之后的投入。

## 5. 非目标(防漂移)

- 不做 Zero-Touch 批量内容生产(那是 ACPF 的赛道,我们的单位是「课堂」不是「文档」)。
- 不做实时多人/直播课堂(重启设计既定)。
- 不为剧情牺牲内容主体(§3.2 护栏为宪法级)。
- 不在 v4 内启用课中实时自适应。
- 不新增第四条主轴。

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| 剧情稀释教学(圣经层最大风险) | 每幕剧情文字预算 + 「去剧情教学仍成立」真检项 + 剧情只占三个固定位置 |
| 教研资产冷启动质量 = 产品天花板 | 起始表小而准(10 条经典误概念均有教育研究背书),人审队列复利扩充,宁缺毋滥 |
| fact-audit 增加 token 成本 | 只对 Deep 幕与含数字/公式/因果断言的幕全查,其余抽查;分级放行减少重写轮次 |
| season 数据与单课模式打架 | seasonId 可空,单课路径零改动;season 功能全程灰度 |
| 闭环数据稀疏(初期学生少) | M3 只做规则型加权(薄弱 KP→幕数),不上统计模型 |

## 7. 评估闭环

- 工程:每里程碑全量真检 + 回归测试锁新行为(与呈现引擎同标准)。
- 产品:追剧意愿(下一课打开率)、一周后留存记忆、误概念前后测(contrast 幕命中项)。
- 资产:三表条目数与人审通过率按月记账——资产增速即护城河增速。
