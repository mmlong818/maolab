# 演示内容呈现系统 · 设计方案

**日期**：2026-06-13
**状态**：方向待用户拍板
**需求来源**（用户 5 项后续任务）：
1. 演示内容的排版多样化
2. 关键知识的呈现形式标准化
3. 特定知识类型的表现形式模板化（如汉字+拼音）
4. 演示内容的排版规则（图文、文图、提示、标注等，需规划）
5. 节点形式多样化（已有漫画、歌曲，需增加；**放置于课程内而不是单独生成**）

> ⚠️ 第 5 项是对 `media-remix-design.md`「课后演绎工坊」定位的**方向修正**：媒体形式从 `course.mediaForms[]`（课后独立入口）改为课程流内的节点。

## 稳定核心（不可变）

- **身份**：猫叔的教学研究室——「研究室手作感」而非平台感
- **审美**：纸质/米色（#fafaf7）、墨色、一课一气质（学科主题 token）
- **人设**：龙老师 + Zero/小陈/段子K/小美，跨一切呈现形式连续
- **体验**：广播剧式课堂（beats 时间轴驱动），一页一语义
- **工程**：LLM 生成 + Zod 校验 + 可单点重写的管线

## 方法论声明

- **MorphologicalAnalysis**（形态分析）→ 任务 1/4：排版是「图位×文位×强调件」的多维组合问题
- **HumanCenteredDesign + BehavioralPsychology** → 任务 2/3：标准化的依据是认知规律（孤立元素效应、双通道编码），不是视觉偏好
- **SystemsThinking** → 任务 5 与整体：媒体节点入课内后，与 beats/学情/导出的系统关系

## 三个结构异质方向

### 方向 A：「排版语法系统」——自底向上的组合语言

**核心思想**：把排版拆成可组合的**原语**，LLM 在生成 atom 时为内容选择一组语法标记，渲染层按语法组装。排版多样性来自组合空间，而非新组件数量。

```
LayoutSpec = 骨架 × 强调件 × 密度
骨架（图文关系）: img-left | img-right | img-top | img-full-bleed |
                 text-only | img-bg(文字压图) | split-vs(左右对峙)
强调件（可叠加）: callout(提示框) | annotation(标注线+引出) |
                 highlight(荧光) | footnote(脚注) | badge(角标)
密度: airy(一句话一屏) | normal | dense(对比表/多要点)
```

- atom payload 增加 `layout?: LayoutSpec`，atoms-worker 的 prompt 给 LLM 选择规则（如「连续 3 个 atom 不得用同一骨架」——节奏强制器在代码层兜底，不靠 LLM 自觉）
- 「汉字+拼音」在此方向中是一种**内容修饰原语**：`<RubyText>` 组件（HTML `<ruby>` 注音），与 MathOrText 同级，按学科+学段自动启用
- 媒体节点（任务 5）：新增 `media-interlude` atom 类型，payload 即现有 SongPayload/ComicPayload，rundown 阶段可插入

**优点**：组合空间大（7 骨架 × 5 强调件 × 3 密度），工程量集中在一套布局引擎，后续零成本扩展；排版规则（任务 4）天然就是这套语法的文档。
**缺点**：LLM 选 layout 的质量需要调教；语法设计错了返工成本高。
**新颖度**：明显差异化（教学产品中少见把排版做成语法交给生成管线）。

### 方向 B：「教学意图驱动」——自顶向下的功能映射

**核心思想**：不让 LLM 直接选排版，而是标注**这段内容的教学意图**，意图决定呈现形式族，族内按节奏轮换变体。排版多样性来自「意图正确 → 形式自然不同」。

```
教学意图（atom.intent）:
  引入(hook) → 形式族: 大图沉浸 / 悬念提问卡 / 生活场景漫画格
  界定(define) → 概念锚点卡 / 田字格字卡(语文) / 公式定音锤
  对比(contrast) → 双栏对峙 / 表格 / 天平图式
  警示(warn) → 易错提示框(红头便签) / 错例打叉演示
  记忆(encode) → 口诀歌片段 / 韵文卡 / 记忆宫殿格
  示范(model) → 工作单 / 笔顺动画 / 过程面板
  收束(anchor) → 便签墙 / 知识地图节点点亮
```

- 每个意图配 2–4 个**呈现变体**，渲染层按「同意图不连续重复」轮换 → 任务 1 的多样化
- 任务 2 的标准化 = 意图→形式族映射表本身（写死在规范里，LLM 只判意图不设计形式）
- 任务 3 的模板 = 形式族中的学科特化成员（田字格字卡、拼音 ruby、笔顺 SVG 属于 define/model 族的语文成员）
- 任务 5 的媒体节点 = encode/hook 意图的「重型成员」：歌曲是 encode 的完整形态，漫画是 hook 的完整形态——**媒体不再是另一类东西，而是意图强度的延伸**（轻：韵文卡 → 重：整首歌）

**优点**：教学逻辑最强（形式永远服务于功能）；标准化和模板化有清晰归属；与 KP 的 Bloom 维度标注（conceptual/procedural/factual）直接对接。
**缺点**：意图分类是新的本体设计，错分意图比错选排版更伤体验；形式族要逐个设计，前期工作量大。
**新颖度**：大胆（把「教学意图」做成排版系统的第一公民，行业内基本没有）。

### 方向 C：「学科呈现包」——按学科垂直打穿

**核心思想**：放弃通用系统，按学科做**完整呈现包**，每包 = 专属 atom 模板 + 排版规则 + 媒体节点偏好 + 标注语言。是「一课一气质」主题系统的内容层延伸。

```
语文包: 田字格字卡(汉字+拼音+笔顺) / 古文对照排版(原文|译文) /
        批注式阅读(眉批/旁批/夹批——中国传统注疏排版!) / 朗读歌谣节点
数学包: 推导黑板 / 数形结合双栏(式子|图象联动) / 错题红笔标注 / 口诀歌
英语包: 单词卡(词形+音标+词源图) / 对话剧场强化 / 语法对比表 / 说唱节点
历史包: 时间轴排版 / 史料档案卡(仿旧纸) / 地图标注 / 评书节点
...每学期挑 1-2 个学科做深
```

- 任务 3 在此方向是主角而非配角：汉字+拼音不是一个组件，而是语文包的核心资产（含田字格、笔顺 SVG 动画、多音字标注规则）
- 任务 5：媒体节点偏好写进包里（语文偏歌谣/评书，英语偏说唱，历史偏漫画）
- 通用 9 atom 保持现状作为兜底

**优点**：单学科体验天花板最高（批注式阅读、数形联动这类东西通用系统永远做不出来）；文化特征强（注疏排版、评书是真正的反 AI 平均感资产）。
**缺点**：边际成本不降（每学科都要重做）；K12 全学段 8+ 学科，覆盖周期长；与通用 atom 系统出现双轨。
**新颖度**：异质化（传统注疏排版进数字课堂，无人做过）。

## 方向对比与推荐

| | A 排版语法 | B 意图驱动 | C 学科包 |
|--|--|--|--|
| 任务 1 多样化 | ★★★ 组合爆炸 | ★★ 族内轮换 | ★★ 包内丰富 |
| 任务 2 标准化 | ★ 语法≠标准 | ★★★ 映射表即标准 | ★★ 包内标准 |
| 任务 3 模板化 | ★★ 修饰原语 | ★★ 族成员 | ★★★ 包核心资产 |
| 任务 4 排版规则 | ★★★ 语法即规则 | ★★ 隐含在族里 | ★ 分散在各包 |
| 任务 5 节点入课 | ★★ 新 atom 类型 | ★★★ 意图强度延伸 | ★★ 包偏好 |
| 工程风险 | 中（布局引擎一次性） | 中高（本体设计） | 低但长尾 |
| LLM 管线改动 | atoms-worker prompt | analyze + atoms-worker | 按学科 prompt 分支 |

**推荐：B 为骨架、A 为肌肉、C 为首发内容的三层混合**——

1. **B 的意图层做决策机制**（who decides）：atom 增加 `intent` 字段，意图→形式族映射表是「关键知识呈现标准」（任务 2）
2. **A 的语法层做执行机制**（how to render）：形式族的每个变体用 LayoutSpec 语法描述而非写死组件，排版规则文档（任务 4）= 语法手册 + 意图映射表
3. **C 取语文包首发**（what to ship first）：第一个学科特化 = 汉字+拼音/田字格/笔顺（任务 3 的指定场景），验证「通用语法 + 学科成员」的扩展模式
4. **任务 5 独立先行**：`media-interlude` atom 类型 + rundown 可插入媒体节点（歌曲/漫画迁入课内），因为它不依赖 1–3 的任何决策，且现有 SongPlayer/ComicPlayer 可直接复用为 atom 渲染器；新增形式按预留 kind 逐个落地（story 评书 → standup 段子K专场 → palace 记忆宫殿）

### 实施分期（混合方案下）

- **P1 媒体节点入课内**（任务 5 前半）：`media-interlude` atom + rundown 插入 + 课程流播放，迁移 Song/Comic — 约 3–5 天
- **P2 意图层 + 语法层地基**（任务 2/4）：intent 字段 + 映射表 v1 + LayoutSpec 布局引擎 + 节奏强制器 — 约 1–2 周
- **P3 语文包首发**（任务 3）：RubyText 拼音组件 + 田字格字卡 + 笔顺 SVG（hanzi-writer 库可直接用）— 约 1 周
- **P4 形式族铺开**（任务 1）：每意图补足 2–4 变体，SlotPresenters 剩余 7 种语义呈现器借此一并迁移 — 持续
- **P5 新媒体形式**（任务 5 后半）：story/standup/palace 逐个实装 — 按需

## 反同质化自检

- ✅ 三方向结构真异质：组合语法（自底向上）/ 功能本体（自顶向下）/ 垂直打穿（按域），不是同一方案换皮
- ✅ 文化特征注入：注疏排版（眉批/旁批）、田字格、评书、口诀——非 Dribbble 化资产
- ✅ 保留创作者偏见：纸质手作感贯穿（红头便签、档案卡、软木板），拒绝通用 dashboard 美学
- ✅ 避免无意义复杂化：意图分类 ≤7 个、骨架 ≤7 种，组合空间够大但本体克制
- ⚠️ 风险点：形式族变体若全由 LLM 自由发挥会回到 AI 平均感——变体必须人工设计定稿，LLM 只做选择
