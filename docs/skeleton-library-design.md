# 教学骨架库（Teaching Skeleton Library）

## 0. 为什么
LLM 自由写每一页 → 噱头/填充/不稳定/"看不懂"。改为：**复用被认可过的结构化骨架**，质量随使用累积。骨架不是纯 PPT，而是**富呈现规格**——美化、娱乐化、具象化、贴近审美，同时科学准确。

要做"针对性设计"，必须先**定义两件事**：知识内容是什么类型、教学意图是什么类型。两者叉乘 → 决定该用哪种具象形式来呈现。

## 1. 知识内容类型（决定"具象化表现形式"）
| 类型 | 本质 | 天然具象形式 | 现有渲染器（种子） |
|---|---|---|---|
| 概念定义 | 某术语/事物"是什么" | 定义卡 + 典型图例 | ConceptDefinitionVisual |
| 结构组成 | 整体由哪些部分构成 | 带标注结构图（可拆解/点击） | (细胞)→需建, 参考 IsoscelesSvg |
| 过程/周期 | 随步骤/时间演变 | 时间轴 / 循环动画 + 关键帧高亮 | MoonPhaseVisual |
| 关系/规律 | 量与量如何关联 | 关系图 / 坐标 / 公式可视化 | SpeedFormulaVisual, 反射定律 |
| 分类/辨析 | 区分易混类别 | 并排对比 + 正反例 + 判别树 | ConceptComparisonVisual |
| 现象/情境 | 可观察事件/真实场景 | 场景插画 / 小剧场（img2img 锚定卡司） | image-caption + 卡司 |
| 操作/技能 | 怎么一步步做 | 分步范例 / 可跟做 | WorkedExample |
| 空间/几何 | 形与位置关系 | 几何图 + 辅助线动画 | IsoscelesTriangleVisual |
| 数据 | 数量分布/趋势 | 图表 | ChartReadingVisual |

> 知识内容还须带**canonical 事实**（取自官方 KP 库），作为科学性护栏：富呈现可以美化，但不能改写事实。

## 2. 教学内容类型（决定"教学弧线"）
| 类型 | 目的 | 弧线要点 |
|---|---|---|
| 引入新概念 | 第一次建立理解 | 钩子 → 定义 → 正例 →（轻）辨析 |
| 辨析易混 | 区分两个混淆点 | 正例 → 反例 → 判别依据 → 练习 |
| 演示原理 | 看清"为什么" | 现象 → 拆解 → 归因 |
| 练习应用 | 迁移到新情境 | 题 → 反馈 → 纠偏 |
| 动手操作 | 做中学 | 示范 → 跟做 → 检查 |
| 归纳收束 | 串成体系 | 要点 → 关系 → 口诀 |

> 通用硬约束（所有骨架继承）：定义先行、单概念推进、页面自足、禁过度噱头、提问克制。

## 3. 骨架 = (知识类型 × 教学类型) → 富呈现规格
```
TeachingSkeleton {
  id, name                         // 如 "周期型·演示原理"
  knowledgeType, teachingType      // 叉乘坐标，用于匹配
  match: { 学科?, Bloom?, 信号关键词[] }
  arc: [ { role, atomType,
           visualForm,             // 具象形式：cycle-anim/structure-diagram/compare/scene/chart/worked...
           slotSpec } ]            // 这一步要填什么（概念名/例句/正反例/答案…），LLM 只填槽不编排
  presentation: { theme, 娱乐元素?, 审美basis }   // 美化/娱乐化层
  accuracy: [ 科学性约束 ]
  provenance: builtin | created | approved
  usageCount, createdAt
}
```

## 4. 闭环：匹配 → 创建 → 沉淀
```
规划某段教学内容
  → 给内容定型(知识类型 + 教学类型)
  → 在库里匹配最契合骨架
       命中 → 用其 arc+具象形式+约束，LLM 填槽生成（不自由编排）
       未命中 → LLM 现场提一个候选骨架(标 created)，本次先用
  → 课程产出 → 用户满意？
       是 → 候选骨架沉淀为 approved，写回库（下次同类直接复用）
       否 → 丢弃 / 调整再生
```

## 5. 与现状的关系
- 现有 21 个 ConceptVisual 渲染器 = **具象形式词汇表的种子**（不是要删，是要"按知识类型"归类、让骨架去调用），不再依赖弱的 GenericConceptVisual 兜底。
- 现有 16 个 `*-rules.ts` + `teaching-taxonomy.ts` = 教学/品类分型的雏形，formalize 成上面两张表。
- 卡司(老师+4同学) + img2img 锚定 = "现象/情境/小剧场"类知识的呈现资产。

## 6. 建设阶段
1. **定义层**：落地两张类型表 + 骨架 schema + 3–5 个种子骨架（包住现有好渲染器）。
2. **匹配注入**：method-plan/rundown 阶段给内容定型 → 选骨架 → 把 arc+具象形式+约束注入生成（填槽不编排）。
3. **创建**：未命中时 LLM 产候选骨架。
4. **沉淀**：采纳入口 → created 升 approved 写回库。
5. **富呈现补全**：按知识类型补齐缺的具象渲染器（如"结构组成"通用可拆解结构图），替代纯文字页。
