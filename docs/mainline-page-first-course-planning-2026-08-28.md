## 1. 本轮决策

主线课程必须从“先生成场景，再由展示层拆页”改成“先确定整堂课的真实投影片，再生成每页内容”。

新的唯一课程呈现主对象是 `LessonPagePlan`。规划阶段结束时，系统必须已经知道：

- 整堂课一共有多少张真实投影片；
- 每张投影片服务哪个知识点和学习目标；
- 每张投影片要求学生看什么、想什么或做什么；
- 提问页和答案页分别是哪两张真实投影片；
- 哪些页面沿用相同版式并增量增加内容；
- 每张投影片对应的教师讲稿和课堂节奏；
- 哪些页面必须有图，以及图承担什么教学证据；
- 每个学习目标最终在哪一页获得可观察证据。

课程总页数不设固定上限。内容放不下、一个页面承担多个认知动作、提问与答案需要分离时，必须拆成更多真实投影片，不能缩字、切换同一页状态或把内容塞进教师备注。

## 2. 用户最终能够完成的操作

新流程应让教师按以下顺序完成一门课：

1. 选择教材、知识点和学情。
2. 查看系统生成的“课程投影片计划”，此时每一页都已经有页号、目的、学生动作、所需证据和图像要求。
3. 在规划环节增删、重排或拆分投影片，确认提问和答案的先后关系。
4. 确认计划后生成投影片正文、讲稿和图像。
5. 在备课页看到与正式课堂完全相同的投影片序列，并在每页下方查看对应讲稿。
6. 对结构不满意时点击“退回规划”，基于旧版本创建新规划版本；旧版本保留，不在原数据上零散修补。
7. 新规划重新确认后，只生成受影响的下游内容，完成检查后再替换当前课堂版本。

## 3. 必须保持不变的行为

- 教材、知识点、学情、角色、已有图像资源和历史课程版本不能被删除。
- 学生投影片仍是老师上课实际投放的全部画面，不另造“板书页”“讲解页”等平行概念。
- 教师讲稿只在备课和教师控制端出现，不能混入学生投影片。
- 课堂、备课预览、缩略图和 PPTX 导出必须使用同一份投影片数据。
- 标题不低于 36px、正文不低于 28px、图表标签不低于 22px、辅助信息不低于 20px；放不下时拆页。
- 旧课程在迁移完成前仍可读取，不能因新模型上线而损坏。

## 4. 当前架构的结构性根因

当前链路是：

```text
知识点
  -> LearningFragment
  -> FragmentSkeletonStep(sceneType)
  -> LessonScene(contentSlots / boardText / studentAction / teacherScript ...)
  -> presentationPagesForScene() 临时拆页
  -> 课堂 / 备课 / 缩略图 / 导出
```

问题不在某一条文案或某一个模板，而在规划单位与交付单位不一致：

- 规划单位是 `LessonScene`，实际交付单位是 `PresentationPage`。
- 一个场景最终可能变成一页、两页或多页，页数直到展示层运行时才确定。
- 提问与揭晓常以同一场景的两个运行状态存在，而不是两个独立页面。
- `contentSlots`、`boardText`、`studentAction`、`evidenceOnScreen` 和 `teacherScript` 可能重复表达同一信息。
- 展示层只能根据字段名称和场景类型猜测什么应给学生看，导致内部说明、答案或重复内容混入投影片。
- 质量门禁主要检查原始场景字段，无法可靠证明最终真实投影片的顺序、受众和内容正确。
- 备课、课堂和导出端各自派生页面后，容易出现页数、标题、配图和内容不一致。

因此，逐页改文案只能掩盖当前一门课的症状，不能阻止下一门课继续产生相同问题。

## 5. 目标生成链

新的链路固定为：

```text
教材与知识点 SourceBundle
  -> 学习契约 LearningContract
  -> 教学进程 LessonArcPlan
  -> 真实投影片计划 LessonPagePlan[]
  -> 投影片正文 PageContent
  -> 最终页级质量审计 PageAudit
  -> 图像与可视化 VisualCompile
  -> 课程版本 CourseRevision
  -> 课堂 / 备课 / 缩略图 / PPTX
```

每一阶段只能补充下一阶段所需信息，不能在后续阶段改变已确认的教学顺序。

### 5.1 SourceBundle

保存教材原文、知识点、出处、年级、学科、学情和允许使用的外部材料。所有事实性结论必须能追溯到来源。

### 5.2 LearningContract

每个知识点必须形成独立、可观察的学习契约：

- `learningGoal`：学生最终能完成的动作；
- `successEvidence`：什么表现说明目标达成；
- `prerequisites`：完成任务前必须具备的知识；
- `misconceptions`：需要显式检验的典型错误；
- `sourceEvidence`：学生判断时可见的材料；
- `transferTarget`：迁移到什么新任务。

禁止使用无法检验的“理解、掌握、感受”等孤立目标。

### 5.3 LessonArcPlan

教学进程只描述学习动作顺序，不描述模板：

```text
定向 -> 接触材料 -> 观察 -> 提出判断 -> 获取解释
     -> 独立练习 -> 获得反馈 -> 总结 -> 迁移
```

某个知识点不需要其中某一步时可以省略，需要多次观察或练习时可以重复。进程不限定总页数。

### 5.4 LessonPagePlan

教学进程必须编译成完整、不可变的真实投影片数组。后续生成不得再增加、删除或暗中拆分投影片。

建议的数据契约：

```ts
type LessonPagePurpose =
  | "orient"
  | "source"
  | "observe"
  | "explain"
  | "question"
  | "answer"
  | "worked-step"
  | "practice"
  | "feedback"
  | "recap"
  | "transfer";

interface LessonPagePlan {
  id: string;
  order: number;
  fragmentId: string;
  knowledgePointIds: string[];
  purpose: LessonPagePurpose;
  audience: "student";
  learningAction: string;
  newInformation: string;
  evidenceExpected?: string;
  sourceRefs: string[];
  contentSpec: VisibleContentSpec;
  visualSpec: VisualContract;
  teacherCompanion: TeacherCompanion;
  pairId?: string;
  layoutGroupId?: string;
  previousPageId?: string;
}
```

关键约束：

- `newInformation` 必须说明本页相对上一页新增了什么，不能重复上一页全部内容而没有新作用。
- `question` 必须通过 `pairId` 指向后一张独立 `answer` 或 `feedback` 页面。
- `answer` 不能与对应 `question` 使用同一个页面 ID。
- 需要“原位增加结论”的连续页面使用相同 `layoutGroupId`，但仍保存为两张完整、不可变的真实投影片。
- 教师讲稿通过 `teacherCompanion` 绑定页面，但不属于学生可见内容。
- 所有需要学生看的“板书”直接进入 `contentSpec`，不再维护另一套 `boardText`。
- 页面内动画只能控制已经可见元素的出现节奏，不能承载新的知识结论、答案或课堂步骤。

## 6. 学生可见内容改为强类型

新的投影片正文不能继续使用 `Record<string, string>` 和任意槽位名称。应使用可审计的强类型联合：

```ts
type VisibleContentSpec =
  | SourceTextPage
  | ImageObservationPage
  | ConceptExplanationPage
  | QuestionPage
  | AnswerPage
  | WorkedStepPage
  | PracticePage
  | FeedbackPage
  | RecapPage
  | TransferPage;
```

每种类型只允许该页面需要的字段。例如：

- `QuestionPage`：题干、作答要求、必要材料、可选配图；没有答案字段。
- `AnswerPage`：对应问题 ID、结论、依据、纠错说明；必须位于问题页之后。
- `SourceTextPage`：完整材料、出处、可选高亮；不能混入讲稿。
- `ImageObservationPage`：可检查图像、观察问题、必要标注；图像缺失即阻断。
- `WorkedStepPage`：本页只呈现一个新的解题步骤，前序步骤只保留理解本步所需的最少内容。

渲染器根据内容类型选择版式，不能根据字数随机换模板。内容过多时由规划器拆页，不由 CSS 缩小字号。

## 7. 规划环节的硬规则

1. 一张投影片只承担一个主要认知动作。
2. 每张投影片必须明确给学生看的内容和学生要完成的动作。
3. 教师内部说明、生成理由、数据键、质量状态和下一步操作不能出现在学生投影片。
4. 提问、作答和答案不能在同一张投影片同时出现。
5. 需要先想后看答案时，必须生成至少两张真实投影片。
6. 一个连续讲解包含多个新步骤时，每个新步骤独立成页；可复用同一版式，但不能切换同一页状态。
7. 有图才能完成的任务，在规划阶段即声明 `visualSpec.required=true`；缺图不能进入发布状态。
8. 教师上课需要展示的文字、结构、图形、结论和总结都必须成为学生投影片内容。
9. 每个知识点至少有一张获取学习证据的页面和一张反馈页面。
10. 每个结论必须能回到本页或前序可见材料，不能要求学生依据未展示的信息回答。

## 8. 页级质量门禁

门禁必须在最终 `LessonPagePlan[] + PageContent` 上运行，而不是只检查来源场景。

### 8.1 结构门禁

- 页面 ID、顺序、知识点归属和页面目的完整。
- 课堂、备课、缩略图和导出的页面数量、ID 与顺序完全一致。
- 每个问题都有后续独立答案或反馈页。
- 每个目标都有可观察证据页。
- 页面之间不存在无新增作用的语义重复。
- 页面计划确认后，渲染阶段没有隐式增页、删页或拆页。

### 8.2 受众门禁

- 学生页只包含学生在该时刻需要看到的内容。
- 教师讲稿、内部链路解释、生成提示和质量备注不能进入 `contentSpec`。
- 不再使用“已完成前两步”“当前只需完成下一步”等没有实际教学材料支撑的系统旁白。

### 8.3 教学门禁

- 问题页无答案、暗示性结论或通过图形编码泄露的答案。
- 答案页同时给结论和可检查依据。
- 分步讲解的步骤顺序真实存在，不能只画装饰性流程线。
- 图像观察、古诗原文、实验数据等材料必须与问题同页或明确位于可回看的前序页。
- 练习与学习目标一致，反馈能指出错误原因和修正动作。

### 8.4 视觉门禁

- 字号符合投影下限。
- 页面没有裁切、重叠、空白占位和无意义留白。
- 图文比例由教学任务决定；观察图优先保证可辨认，文本页优先保证阅读节奏。
- 版式连续页的核心元素位置稳定，只增加本页的新信息。
- 所有必需图像已生成、可加载并通过真实尺寸检查。

任何阻断项存在时，不得把课程标记为 `ready`。

## 9. 备课、课堂与导出统一

四个消费端只能接收同一份 `CourseRevision.pages`：

```text
CourseRevision.pages
  -> ClassroomSlide
  -> PrepSlide + TeacherCompanion
  -> Thumbnail
  -> PPTX Slide
```

禁止消费端再次调用类似 `presentationPagesForScene()` 的拆页逻辑。

备课页展示顺序固定为：

1. 真实学生投影片；
2. 该页教师讲稿；
3. 该页授课节奏和必要提醒。

不再展示生成原因、槽位名称、内部链路、执行器、运行状态或与上课无关的技术信息。

## 10. “退回规划”的版本机制

课程需要显式版本和阶段：

```ts
type CourseRevisionStatus =
  | "planning"
  | "plan-approved"
  | "generating"
  | "review"
  | "ready"
  | "archived";
```

规则：

- 点击“退回规划”时，从当前版本复制来源和学习契约，创建新的 `planning` 版本。
- 当前 `ready` 版本继续可用，不被覆盖。
- 计划调整后生成新的 `planRevisionId`。
- 所有正文、图像、审核结果和导出文件都绑定 `planRevisionId`。
- 计划变化后，旧计划对应的下游产物标记为过期，不能混入新版本。
- 新版本通过页级门禁和真实检查后，教师再将其设为当前课堂版本。
- 不允许通过直接改数据库字段来“修好”当前版本。

## 11. 旧模型的处理边界

新课程不再把 `LessonScene` 作为呈现主对象。旧字段按以下方式处理：

- `contentSlots`：仅由旧课适配器读取，新课程改用 `VisibleContentSpec`。
- `boardText`：新课程取消；学生要看的内容写进页面，教师提示写进讲稿。
- `studentAction`：收敛为页面的 `learningAction` 和强类型任务字段。
- `evidenceOnScreen`：改为质量审计从页面内容推导，不再重复手写。
- `visualFocus`：收敛到页面目的、标题和视觉契约。
- `teacherScript`：保留，但只能存在于 `TeacherCompanion`。
- `beats`：只允许控制同一页面内的微动画，不得生成教学内容或揭晓答案。

旧课程通过只读适配器转换成临时页面供查看；不能在读取时自动回写或批量改库。

## 12. 实施顺序

### 阶段 A：建立页面规划内核

- 新增 `CourseRevision`、`LearningContract`、`LessonArcPlan` 和 `LessonPagePlan` 类型。
- 将骨架库从 `sceneType` 序列改为学习动作和页面目的序列。
- 新增确定性页面规划器和计划快照测试。
- 暂不改现有课堂消费、正文填充和图像写入；新建课程只随原有课程载荷保存可选规划快照。

完成标准：输入同一知识点和学情时，页面数量、顺序、目的和配对关系稳定可复现。

### 阶段 B：建立强类型页面内容生成

实现状态：正文契约、逐页生成器、版本快照与正文门禁已完成；等待阶段 C/D 提供计划确认入口并切换正式消费端。

- 为每种页面目的定义 `VisibleContentSpec`。
- 内容生成只能填充已存在的页面计划，不能改变页面数量和顺序。
- 建立问题与答案隔离、教师内容隔离、来源绑定和语义去重门禁。

完成标准：任何页面都能在不读取任意槽位名称的情况下确定学生可见内容。

### 阶段 C：统一四个消费端

实现状态：已完成。新课程页面数组由 `pageContent.pages` 一对一驱动四端，旧课程保留只读兼容。

- 课堂、备课、缩略图和 PPTX 改为消费同一页面数组。
- 移除新链路中的展示层拆页和同页揭晓状态。
- 保留旧课只读适配器。

完成标准：四端页面 ID、数量、顺序、标题、正文和配图一致。

### 阶段 D：加入版本化回退规划

- 增加课程版本状态和“退回规划”动作。
- 计划修改产生新版本，旧课堂版本保持可用。
- 下游内容按 `planRevisionId` 失效和重建。

完成标准：教师可在不修改旧版本的情况下重新规划、生成、检查并替换课程。

### 阶段 E：用正式链路重建《芣苢》

- 从原教材知识点和原文重新建立学习契约。
- 由新规划器生成全部真实投影片，不复用当前手工修正版作为生成输入。
- 当前手工修正版只作为问题对照，不作为新课模板。
- 完成学生投影片、教师讲稿、配图、页级门禁和真实浏览器检查。

完成标准：课程中没有无作用重复、内部说明、提问泄底、缺失原文或图像，以及四端不一致。

### 阶段 F：十门真实课程验证

至少覆盖语文、数学、英语、物理、化学、生物、历史、地理、道德与法治、艺术或科学中的十个真实知识点。

每门课执行：

- 规划结果审核；
- 页面级静态门禁；
- 真实备课操作；
- 真实课堂逐页操作；
- 缩略图和 PPTX 一致性检查；
- 1280x720 投影尺寸视觉检查；
- 心理学、视觉艺术、教育学、特级教师和产品经理五个视角的产出评审。

发现共性问题时只修改规划契约、内容类型、生成器或门禁，然后重新生成测试课程；禁止直接修十门课的数据。

## 13. 《芣苢》用于验证新规划器的页面骨架

以下只用于验证规划能力，不是最终文案，也不固定最终页数：

1. 学习问题：本课要判断叠词与重章叠句分别产生什么表达效果。
2. 完整原文：学生可以看到全文和出处。
3. 观察不变部分：标出各章重复的句式和词语。
4. 形成“重章叠句”概念：根据观察给出定义和结构证据。
5. 观察变化部分：按诗章顺序标出六个采摘动词。
6. 比较动作推进：只呈现动词顺序和可检查的动作变化。
7. 形成“叠词”概念：结合原文词例说明形式与语气作用。
8. 综合表达效果：区分结构反复与词语反复各自承担的作用。
9. 误区提问：给出一个混淆两种手法作用的判断，不显示答案。
10. 误区核查：在下一张真实投影片给出结论和原文依据。
11. 独立练习：使用新的诗句或片段判断手法与表达效果。
12. 练习反馈：给出判断标准、结论和修正依据。
13. 本课总结：只保留需要学生带走的概念、证据和分析句式。
14. 迁移任务：面对新材料独立完成同类分析。

连续页面可以使用相同版式和固定元素位置，但每一个编号都必须是可导航、可导出、可审计的独立页面。

## 14. 实现前验收标准

只有以下条件全部明确后才进入编码：

- `LessonPagePlan` 是新课程唯一页面顺序来源。
- 规划阶段能够看到全部实际页面，而不是场景摘要。
- 问题和答案以独立页面表示，不存在同页状态切换。
- 所有学生可见内容都使用强类型结构。
- 教师讲稿与学生内容在数据层分离。
- 页面计划确认后，后续生成不得改变页数和顺序。
- 四个消费端不再自行拆页。
- 旧课有只读兼容方案，新课不继续写旧结构。
- “退回规划”通过新版本实现，不覆盖现有课堂版本。
- 页级门禁和十门真实课程验证方案可执行。

本规划通过后，第一批实现只做阶段 A，不直接重写《芣苢》或批量迁移课程。页面规划内核通过测试后，再按阶段推进。
