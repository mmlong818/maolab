## 物理

> 定位延续总纲(`2026-07-23-typed-content-forms-spec.md` §0):不做「教材第二版」。物理内容的专属命题是——**看不见的东西要被画得看得见**(力、电流、光线、运动趋势本身都不可直接观察),同时这份"看得见"必须**可核验为真**,错一个矢量方向/错一个电路符号/错一条光路,教学价值就归零。

### 方法论声明(creation.md,物理特化)
- **第一性原理**:先问每类内容的"本质结构"是什么——受力分析的本质是**矢量代数**(方向+大小+合成规则),电路图的本质是**图论拓扑**(节点+连接关系,不是"画得像不像"),光路图的本质是**几何光学定律**(反射定律/折射定律/透镜成像公式,是可计算的确定性问题,不是自由绘图),运动图像的本质是**函数图像**(斜率/截距/面积的数学意义),实验装置的本质是**变量控制逻辑**(不是器材写生)。视觉语法必须从本质结构直接导出。
- **跨域移植**:借入工程制图(CAD 标注线/仪表读数)、PCB/电子产品的"通电高亮"隐喻、游戏引擎的 Debug Draw 矢量渲染、金融图表的关键点标注、DAW 多轨对齐、看板管理(Kanban)的结构化信息卡——都是物理教学从未认真借用过的现代视觉语言。
- **反同质自检**:六类内容禁止共享同一套"卡片+图标+accent色"皮肤;下文每类给出的甲乙两方向在**构图逻辑**层面互斥(仪表读数带 vs 推导轨道、静态工程图纸 vs 分镜叙事、发光通路 vs 拓扑网格、光线追踪剧场 vs 几何证明作图、事件锚点仪表流 vs 多轨叠合乐谱、标注剖面 vs 变量看板),不是换色换字体的皮肤变体。

### 贯穿全学科的一条架构决策:「渲染器管定律,LLM 管取值」
物理内容对"正确性可核验"(地基 3)的要求比其他学科更硬,因为一部分内容**本身就是确定性物理定律**,不该指望 LLM 每次都精确生成正确的几何/角度:

- **光路图**是这条铁律的主战场:反射定律(入射角=反射角)、折射定律(Snell 定律)、凸透镜/凹透镜成像公式都是**渲染器可以直接计算**的确定性数学,不应该让 LLM 自由画光线角度或猜"物在几倍焦距外"。因此 §光路图 的数据结构只要求 LLM 提供**原始物理量取值**(物距/焦距/入射角/折射率),真正的光线路径由渲染端一个几何光学规则引擎**算出来**——错误光路在架构上不可能被生成,不依赖事后审核。
- **受力分析/运动图像/电路拓扑**则不同:矢量的大小方向、运动数据点、元件连接关系,都是题目给定的"已知条件"(由 fact-audit 环节保证内容准确),渲染器的职责只是**精确、不失真地画出被给定的数据**,不需要引擎去"推导"出它们。
- 两种职责必须在生成规则(`fill-scenes.ts` CONTENT_FORM_RULES)里写清楚区别,防止未来误把光学规则引擎的活派给 LLM,或反过来让渲染器去"猜"受力分析该长什么样。

### 电路符号红线
中国教材电阻符号是**长方形**(国标 GB/T 4728),**不是**欧美教材常见的锯齿形(zigzag)——渲染器必须按国标/人教版画法出符号,否则学生对照课本会产生"课本画的和屏幕上不一样"的认知冲突,这比"不好看"更严重,是正确性红线,不是审美选择。

### 公式+物理量+单位(定量关系卡)

**教育内核**:物理公式不是要背的符号串,是**物理量之间的定量关系**——符号(v)、单位(m/s)、数值三者能否对上号,决定学生是否真正建立了"量"的概念,而不是记住一个字母等式。

**要超越的教材形态**:印刷体黑字居中的等式 + 旁注小字单位说明,公式与单位是割裂的两行字,量纲从不作为视觉主角出现。

**超越设计·方向甲【量纲仪表读数带 dimension ledger】**:公式本体仍走已有 MathText 行内 LaTeX 大字居中,下方铺一条水平"仪表读数带"——每个物理量做成一枚胶囊标签(符号+数值+单位),胶囊按角色配色(已知量/未知量/常量三色区分),胶囊之间用等号/斜杠形态的连接符排布,未知量胶囊留白或问号占位、边框做成虚线"待求"质感,背景可加极淡的仪表刻度纹理(不抢主体)。为什么现代:直接挪用工程制图的尺寸标注线(dimension line)和智能仪表盘"数值即状态"的视觉隐喻,把公式从"抄黑板"变成"读一块面板"。

**方向乙【推导轨道 derivation rail】**:不呈现孤立公式,呈现"这条公式怎么来的"最小推导链——横向节点轨道,每个节点是一步推导(定义 → 代入 → 化简 → 结果),节点间用箭头连接,每个节点旁挂一个类似代码编辑器 inline type hint 的小标签(该步涉及的符号+单位)。为什么现代:借代码编辑器"内联类型提示"和函数式管道可视化的语言,让公式呈现为**过程**而非**答案**,回应"公式怎么来的"这个物理教学的常年痛点。

**学段四档**:
| 学段 | 处理 |
|---|---|
| 低小 | 一般不出现符号级定量关系;若有,做"1 米有多长"式实物对照插画,不出现字母符号 |
| 高小 | 方向甲简化版,1–2 个物理量胶囊,重点建立"符号=某个量"的联结感,刻度纹理卡通化 |
| 初中 | 甲/乙皆可,符号规范全面上线,推导步数 2–3 步 |
| 高中 | 方向乙为主力,多步推导+多物理量同屏,去插画装饰,仪表带方向的刻度做成示波器/万用表读数质感 |

**数据结构建议**:公式本体沿用现有 `boardText`/槽位内联 `\( … \)`(CONTENT_FORM_RULES.physics 已覆盖,不改)。新增两枚**附加槽**(不替代必填槽):
- `quantityLedger`:每行一个物理量,`符号|中文名|数值或?|单位|角色(given/unknown/constant)`。例:
  ```
  v|速度|?|m/s|unknown
  s|位移|100|m|given
  t|时间|20|s|given
  ```
- `derivationSteps`(仅方向乙触发):每行一步,`表达式|这一步在做什么`。例:
  ```
  v=\frac{s}{t}|定义式:速度=位移除以时间
  v=\frac{100}{20}|代入已知量
  v=5\,\mathrm{m/s}|化简得结果
  ```

**复用**:系统 B 无对应 kind;`worked-example-board.steps`(stepNum/action/explanation)在"步骤序列"的抽象形状上与 `derivationSteps` 同源,可参考其字段命名,但系统 A 走自己的行编码,不直接复用对象结构。

**优先级**:P1(几乎每节课都出现,覆盖面最大;现状 MathText 已能顶底线显示,只是呈现平庸,非空白)。

### 受力分析图(矢量·力的合成)

**教育内核**:力是矢量——受力分析教的是"把看不见的力,变成可核验方向/大小/合成关系的箭头系统",平行四边形法则/三角形法则的几何关系必须精确,画错方向就是教错了。

**要超越的教材形态**:方块代表物体,周围几条简笔画箭头标 F₁/F₂/mg/N,箭头长度不严格按比例,构图随手一画的既视感。

**超越设计·方向甲【工程受力蓝图 blueprint free-body】**:物体用极简几何图形(圆/矩形/图标化剪影)居中,箭头是**矢量本身**——起点在作用点、方向严格按角度、长度严格按比例、箭头头部是工程制图标准实心三角形(非简笔画箭头),每支箭头贴一枚数值胶囊(符号+数值+单位),按力的类型分类配色(重力深灰/支持力蓝/摩擦力橙/拉力绿)并给出图例角标,背景衬极淡 CAD 网格纸质感。为什么现代:直接挪用工程力学制图与游戏引擎 Debug Draw 矢量可视化的专业语言——精确、克制、不卡通。

**方向乙【合成分镜 vector-composition strip】**:不是单帧受力图,是分镜式多联呈现矢量合成过程——第一格两个分力独立展示,第二格平移首尾相接(虚线辅助线做平行四边形/三角形作图),第三格合力箭头出现并加粗强调,格间用编号+箭头连接。为什么现代:借漫画分镜(storyboard)叙事语言,让矢量合成这个**过程性**的几何操作被"讲故事"式呈现,而非一张静态终图。

**学段四档**:
| 学段 | 处理 |
|---|---|
| 低小 | 不做严格矢量合成(超纲);"推/拉"方向感用具象插画(小孩推箱子+箭头指向),箭头卡通粗描边暖色 |
| 高小 | 方向甲简化版,单力或两力,箭头保留一点圆角友好度,不强制严格比例(教学重点是方向感非精确值) |
| 初中 | 甲/乙皆可,箭头严格按比例与角度,支持 3–4 力同屏,首次引入图例,分类配色规范上线 |
| 高中 | 方向乙合成分镜为主(常配合动力学计算),角度标注精确数值(如经典 37°/53°),背景网格质感增强,支持多物体多级受力(滑轮组/斜面系统) |

**数据结构建议**:新增 `forceVectors` 槽。每行一个矢量:`标签|类型|大小|单位|角度|颜色角色`,角度约定**以物体右侧水平方向为 0°,逆时针为正**(须在生成规则里写死,防止 LLM 自定义坐标系导致图与图之间不一致)。例:
```
mg|重力|50|N|270|gravity
N|支持力|50|N|90|normal
f|摩擦力|10|N|180|friction
F|拉力|20|N|30|applied
```
可选 `forceObject` 槽描述受力物体一句话(如"木块静止于水平面");方向乙额外用 `vectorCompositionSteps`,每行一步的合成说明文字。

**复用**:系统 B `math-model.geometry` 当前 `values: Record<string,unknown>` 未定义矢量语义,不直接复用;拓扑/角度数据形状是本次新增,独立成槽。

**优先级**:P0(初高中最高频、最需要精确图示的内容;现状完全空白,画错方向=教学事故,教育风险最高)。

### 电路图(元件符号·拓扑)

**教育内核**:电路图教的是"看懂连接关系"——元件规范符号 + 串并联拓扑判断,是欧姆定律/焦耳定律等电学计算的先导语言。

**要超越的教材形态**:黑白线条 + 标准符号,规整但呆板,像工程蓝图的缩印件,是"看不懂电路图"学科恐惧感的常见来源。

**超越设计·方向甲【发光电路板 illuminated schematic】**:元件用规范符号(电池长短线、开关、灯泡圆圈打叉、电流/电压表圆圈+字母、**电阻用国标长方形**),导线走直角规范布线,通路部分用高亮色(亮蓝发光线条+微光晕)表示电流路径,断路部分灰色虚化。为什么现代:挪用 PCB/智能家居 App"通电即高亮"的视觉隐喻,给"电流方向"这个抽象概念一份看得见的生命感,同时符号规范分毫不让。

**方向乙【模块拓扑网格 modular topology grid】**:不画连续导线,把电路抽象成"节点-模块"网格——每个元件是一张独立圆角矩形模块卡(内画规范符号+数值标注,如"R1 5Ω"),模块间用简洁正交连线表示关系;并列模块横向对齐自然读出"并联",纵向连接自然读出"串联",不需要额外文字标注"这是并联"。为什么现代:借电路网表(netlist)可视化 / Node-RED 一类低代码流程编排工具的模块化连线语言,让拓扑结构本身说话,降低认知负荷。

**学段四档**:
| 学段 | 处理 |
|---|---|
| 低小 | 一般不出现规范符号(超纲);电池+灯泡+开关闭合回路用具象拟物插画,强调"通了/断了"的直觉 |
| 高小 | 引入规范符号但线条加粗圆角化,方向乙模块卡形式更友好、容错率高,数值标注可选 |
| 初中 | 甲/乙皆可,国标符号全面上线,方向甲电流高亮强化"电流看得见",数值标注必须完整(为计算铺垫) |
| 高中 | 方向乙拓扑网格为主(复杂度上升,含电容/多回路/桥式电路),视觉转极简黑白+克制强调色,去发光效果 |

**数据结构建议**:新增两枚附加槽:
- `circuitTopology`:每行一个元件,`元件id|类型|数值|单位`,类型枚举 `battery/resistor/bulb/switch/ammeter/voltmeter`。
- `circuitConnections`:每行一条直接连接,`元件idA-元件idB`;渲染器按连接关系做简单分层布局,**多元件共享同一对节点 → 判定为并联**,依次串接 → 判定为串联,不依赖 LLM 显式声明"这是并联"。
```
circuitTopology:
B1|battery|6|V
R1|resistor|5|Ω
R2|resistor|10|Ω
S1|switch||

circuitConnections:
B1-R1
B1-R2
R1-S1
R2-S1
```
（示例:R1、R2 并联后与 B1、S1 串联)可选 `circuitState`(`closed`/`open`)控制方向甲通路高亮 vs 断路灰化。

**复用**:系统 B `concept-map` 的 `nodes/links` 在"图论数据形状"(id+label 节点、from/to 连接)上可参考抽象结构,但视觉与语义(概念图 ≠ 电路规范符号)完全不同,只借形状不借视觉。

**优先级**:P0(初中电学刚需,现状空白,"看不懂电路图"是常见学困点)。

### 光路图(成像·反射折射,通用化)

**教育内核**:几何光学教的是"光线怎么走决定像在哪、像是什么样"——反射定律、折射定律(方向定性 + 角度关系)、平面镜/凸透镜/凹透镜成像作图规则,是光学的核心语言。现状 `RefractionSimulation` 只是一张**写死的折射光路 SVG**,只能演示"光从一种介质弯折进入另一种介质"这一种场景,覆盖不到平面镜反射、透镜成像(实像/虚像/放大缩小/正立倒立)——这是本次必须根治的"假通用"缺口,新设计必须能装下五种场景:平面镜反射 / 凸透镜成像 / 凹透镜成像 / 折射 / 三棱镜色散,而不是继续只服务折射一种。

**要超越的教材形态**:黑白细线 + 虚线主光轴 + 箭头,"三条特殊光线"套路化机械作图,呆板、无重点提示。

**超越设计·方向甲【几何证明作图仪 optics protractor board】**:法线用短虚线+直角标记(90° 小方块符号,规范几何作图语言),入射/反射/折射光线用不同色实线区分(入射中性灰、反射蓝、折射橙),关键角处画小圆弧+精确角度数值标注,背景衬淡量角器网格纹理。为什么现代:挪用精密仪器制图与 GeoGebra 一类几何画板软件的专业作图美学,把光路图从"课本简笔画"升级成"可以被复核的几何证明",直接呼应地基 3。

**方向乙【光线追踪剧场 raytrace stage】**:借鉴 3D 渲染/游戏引擎光线追踪的调试可视化——光线是带渐变发光效果的光束(暖黄色,击中界面/透镜后颜色微变代表折射发生),法线/主光轴等辅助线弱化为极简虚线"脚手架",玻璃透镜用半透明蓝色渐变材质、镜面用金属灰渐变,成像位置用光斑/焦点符号强调。为什么现代:直接挪用 CG 渲染光线追踪的专业视觉语言,让光路图从"考试作图步骤"变成"这东西真的在模拟光"的沉浸感。

**学段四档**:
| 学段 | 处理 |
|---|---|
| 低小 | 不做规范作图(超纲);用具象类比插画("影子游戏"/"镜子里的我"),不出现法线/入射角术语 |
| 高小 | 引入"光沿直线传播/镜面反射"直觉,方向乙简化版(光束+镜面),不标注角度数值 |
| 初中 | 甲/乙皆可(反射定律+平面镜/凸透镜成像三大考点),法线/角度规范标注上线,虚像用虚线轮廓、实像用实线轮廓严格区分 |
| 高中 | 方向甲几何证明作图为主(常结合折射率/临界角计算),角度精确到数值,支持多光线/多界面(三棱镜色散、光纤全反射) |

**数据结构建议(核心是"渲染器算,LLM 只给取值"这条架构决策的落地)**:新增 `opticsScene` 槽,第一行声明场景类型,随后按类型给**原始物理量**,不给光线路径本身:
```
scene|convex-lens
u|30            # 物距(cm,相对焦距的具体数值,由题目条件给出)
f|10            # 焦距(cm)
h|4             # 物高(相对单位)
```
渲染器内部按薄透镜成像公式 `1/f = 1/u + 1/v` 与放大率公式**计算**像距/像高/正倒/虚实,并用三条标准特殊光线(平行光过焦点、过光心不偏折、过焦点光线平行出射)算出光路——错误光路在架构上不可能出现。平面镜:给物体坐标+镜面位置,渲染器按镜面对称关系计算像位置。折射:给 `n1|n2|theta1`(入射角),渲染器用 Snell 定律 `n1·sinθ1 = n2·sinθ2` 算出折射角。反射:入射角由渲染器自动对称生成反射角,不要求 LLM 给两个独立角度。

**复用**:系统 B 无光学专属 kind,`math-model.geometry` 长期可扩展出光学子类,但当前 schema 过于自由(`values: Record<string,unknown>`)未定义具体字段,系统 A 独立实现更快更可控,暂不牵动系统 B。

**优先级**:P0(初高中核心考点,现状"假通用"风险最高——`RefractionSimulation` 覆盖不到的场景等于完全空白,必须优先根治)。

### 运动图像(v-t / s-t · 运动规律)

**教育内核**:运动图像教的是"图像形状=运动性质"的抽象跃迁——斜率代表速度/加速度,截距代表初始值,曲线下面积代表位移,是物理与数学函数图像的交汇点。

**要超越的教材形态**:坐标轴 + 一条折线/曲线 + 简单文字说明,平铺直叙,没有"图像即故事"的解读引导。

**超越设计·方向甲【运动仪表流 kinematics dashboard】**:坐标系规范(轴/单位标注齐全),在斜率变化的转折点加"事件锚点"标注——类似股票 K 线图/心电图的关键点标注,悬浮胶囊写明"这一段:匀速/加速/减速/静止"及对应数值,图像旁配一条迷你"运动意图条"(一个小圆点/小车图标沿对应空间位置移动,暗示这条曲线对应的具体运动),分段配色。为什么现代:挪用金融图表/健康监测应用的"图像叙事化"标注手法,让学生像读心电图一样读懂运动图像每一段的物理意义。

**方向乙【多轨叠合乐谱 stacked-track score】**:借 DAW(音频编辑软件)多轨时间线或乐谱多声部对齐的语言——把 v-t 与 s-t(或再加 a-t)纵向堆叠对齐同一时间轴,轨道左侧标轨道名("速度""位移"),关键时刻用一条贯穿全部轨道的竖向参考线连接(如播放头),强调"同一时刻、不同物理量"的对应与积分/微分关系。为什么现代:直接挪用专业音视频编辑软件的多轨对齐视觉语言,精确传达运动学"图像家族"之间的数学关系,是进阶/竞赛级呈现的野心方向。

**学段四档**:
| 学段 | 处理 |
|---|---|
| 低小 | 不适用严格坐标图(超纲);"运动快慢"用具象比较插画(龟兔赛跑式),不画坐标轴 |
| 高小 | 极简坐标图(距离随时间变化),方向甲简化版,事件锚点用友好图标(如"小车在这里停下了⏸"),不引入斜率/加速度概念 |
| 初中 | 方向甲为主(匀速/变速运动是重点),事件锚点标注规范化,引入 v-t 图面积=位移的定性强调(阴影区域) |
| 高中 | 方向乙多轨叠合为主(v-t/s-t/a-t 互推是重点),坐标轴学术级规范,事件锚点转精密数值标注,去插画装饰 |

**数据结构建议**:新增 `motionGraph` 槽。首行声明轴类型 `axis: v-t`(或 `s-t`/`a-t`),随后每行一个数据点 `时间|数值|阶段标签`,同一时间点重复出现表示分段拐点(渲染器按相邻点连线并按阶段标签分色):
```
axis: v-t
0|0|加速
2|6|加速
2|6|匀速
5|6|匀速
5|6|减速
8|0|减速
```
方向乙多轨叠合:允许槽内出现多个 `axis:` 块,渲染器按声明顺序纵向堆叠对应轨道。

**复用**:系统 B `math-model.coordinate` 在"坐标点序列"抽象概念上同宗,但 schema 未定义具体 points 数组结构,系统 A 独立编码,不直接复用。

**优先级**:P1(初高中高频考点,现状空白;但数据本身由题目给定+可由 fact-audit 校验,不像光路图那样必须依赖渲染器内置定律引擎,风险低于受力/电路/光路三类,故排后)。

### 实验装置图(实验设计)

**教育内核**:实验装置图教的不是"这是个什么仪器",是**控制变量的空间化呈现**——自变量/因变量/控制变量的关系,是"为什么这样搭建能验证这条规律"的实验设计思维。

**要超越的教材形态**:写实素描风格的仪器插画(铁架台上的装置手绘图),偏"美术课代表画的示意图",不体现变量关系,只体现"器材长什么样"。

**超越设计·方向甲【实验台标注剖面 lab-bench annotated】**:装置本体用简化几何图标化插画(非写实素描,类似现代科学教育 App 的器材图标体系——烧杯/铁架台/弹簧测力计/滑轮组统一线性图标风格),关键测量点用标注气泡+引线标出读数,构图按"自变量器材(如砝码组,一侧强调色)→ 因变量读数器材(如测力计,另一侧强调色)"的空间逻辑排布,视觉动线暗示因果关系。为什么现代:挪用 PhET 一类现代科学模拟应用/说明书级"图标化拆解图"语言,比写实素描更干净,更能让"变量关系"这个教学重点冒出来,而不是被器材细节淹没。

**方向乙【变量控制看板 variable-control board】**:装置插画只占画面一角(缩略图标级),画面主体是一张"实验看板"——三栏卡片结构(控制变量 / 操纵变量 / 观测变量),每栏配小图标+简短文字,底部一条实验结论横幅收尾。这里文字结构占主体、图退为点缀,是刻意越界地基 2「图辅文主」的合理例外——因为该内容类型的教育内核本来就是"变量逻辑"而非"器材长相",结构化信息本身就是"图",不是对地基的违反。为什么现代:挪用现代管理看板(Kanban)/产品需求文档(PRD)的信息卡片视觉语言,把实验装置图从"画得准不准"的美术任务,转成"设计逻辑是否清楚"的结构化信息设计。

**学段四档**:
| 学段 | 处理 |
|---|---|
| 低小 | 方向甲简化版,装置图标卡通化(大圆角暖色拟物,生活化器材如放大镜/水杯),不引入自变量/因变量术语,用"我们改变了什么/我们看到了什么"口语标签 |
| 高小 | 方向甲为主,图标化程度提升接近教育 App 质感,引入"要改变的/要测量的"半正式说法,画面仍以图示为主导 |
| 初中 | 甲/乙皆可,方向乙三栏变量看板首次上线成为教学重点呈现,规范使用"自变量/因变量/控制变量"术语 |
| 高中 | 方向乙看板为主,信息密度提高(支持多组对照实验并列),装置图标转极简线条(去卡通化),可叠加数据记录表 |

**数据结构建议**:新增 `experimentSetup` 槽,前缀行结构,直接移植系统 B `experiment-board` 的字段语义但拆分更精确(`conditions` 拆为 independent/control 两类):
```
objects: 弹簧测力计,滑轮,砝码组
independent: 砝码质量
dependent: 测力计读数
control: 滑轮组数量不变
conclusion: 拉力与被提起物体重力成正比
```
`control` 允许出现多行(多个控制变量),渲染器按前缀分栏落位。

**复用**:直接复用系统 B `VisualSpec.experiment-board` 的字段命名与语义(`objects/conditions/observations/conclusion` → 拆分映射为 `objects/independent/dependent/control/conclusion`),移植的是**数据结构语义**,视觉按本文方向甲/乙全新设计,不搬系统 B 现有的功能性外观。

**优先级**:P1(覆盖全学段、是初中科学方法教学核心,但"正确性红线"没有矢量/电路/光路三类紧——排在其后,不排 P2 是因为实验设计是物理教学法的根基,不能拖)。

## 视觉分工标注(位图 / 矢量)

> 承接总纲 §0.7(位图 vs 矢量精绘分工铁律)+ §0.8(精准度打磨)。校准样例见 `raster-upgrade-demo.html` 「02·物理·受力分析」一节——写实斜面木块位图(`_raster/incline.png`,gpt-image-2 实拍)+ 精确力矢量矢量层,已证明档位。**物理是「写实情境位图 + 精确矢量叠加」混合的典型学科**:空间感/材质感/光影交给位图,方向/角度/数值/符号一律交给矢量——矢量层画错就是教学事故,位图层不够好看只是遗憾,两者后果不对等,不能互相替代。逐类标注如下。

### 公式+物理量+单位(定量关系卡)
- **位图部分**:无。该类型是纯符号/数值排版内容,不涉及具象实物,不占用生图管线——仪表读数带的刻度纹理、推导轨道的节点连接线都是 CSS/SVG 装饰,不是"示意插画"。
- **矢量部分**(全部内容):公式本体 MathText/LaTeX、物理量胶囊标签(符号+数值+单位+角色配色)、胶囊间等号/斜杠连接符、推导轨道节点与箭头、inline type hint 小标签、仪表刻度装饰纹理。
- **白为主**:纯白卡面 + 胶囊配色克制(已知/未知/常量三色),不存在位图深色边界问题。

### 受力分析图(矢量·力的合成)
- **位图部分**(校准样例已验证,`_raster/incline.png`):受力物体所处的写实情境——斜面、木块、小车、滑轮组、绳索、桌面等实物与材质光影,按学段取 `stylized-teaching`(初中前,风格化教学插画质感)或 `diagram-accurate`(高中,精密写实);背景近白或浅中性色、不抢焦点;**图内绝不出现任何文字/箭头/标签**,这些一律由矢量层叠加。
- **矢量部分**(必须精确,错即教学事故):力矢量箭头——起点固定在作用点、方向按角度数值精确、长度按大小比例、箭头头部为实心三角形(工程制图标准,非简笔画);角度标注弧线+数值(如 37°/53°);力类型分类配色图例(重力/支持力/摩擦力/拉力);数值胶囊标签(符号+数值+单位);方向乙【合成分镜】额外的平移辅助线(虚线首尾相接、平行四边形/三角形作图线)。
- **白为主**:位图铺满图卡但收在卡内、幕面其余留白;方向甲"淡 CAD 网格纸质感"走矢量/CSS 纹理,叠加在位图之上或位图周边留白区,不整幅出血。

### 电路图(元件符号·拓扑)
- **位图部分**:仅限低小/高小的"具象拟物"路径——电池、灯泡、开关等实物写实或拟物插画(`stylized-teaching`,暖色友好质感),用于建立"电从哪里来、灯泡为什么会亮"的直觉,图内不出现导线拓扑或符号标注。初中及以上不再使用位图,电路图整体转为纯矢量。
- **矢量部分**(初中起为主体,全部内容):电池长短线、开关、灯泡圆圈打叉、电流表/电压表圆圈+字母、**电阻国标长方形符号**(红线,绝不画欧美锯齿形 zigzag)一律矢量绘制;导线走直角规范布线;方向甲的通路高亮/断路灰化用矢量描边+发光滤镜实现(非位图);方向乙的模块拓扑网格(圆角矩形模块卡+正交连线+数值标注)全部矢量/HTML。
- **白为主**:低学段拟物插画收在图卡一角或整卡内,不影响幕面留白;初高中电路图本身近白/浅灰底 + 高亮强调色,天然贴合白为主。

### 光路图(成像·反射折射)
- **位图部分**(可选,绝不承担光路本身):方向乙【光线追踪剧场】可选一层材质衬底——透镜玻璃质感、镜面金属光泽、棱镜折射质感,`stylized-teaching` 或 `atmosphere` 档,仅作氛围/材质点缀,近白或极浅背景,**图内不含任何光线、角度或标注**;方向甲【几何证明作图仪】通常无需位图,纯矢量量角器网格即可。
- **矢量部分(架构红线,不可位图化)**:法线、入射/反射/折射光线路径、关键角度圆弧+数值标注、成像位置与虚实(虚线/实线轮廓严格区分)、三条特殊光线——**光线角度必须由渲染器按反射定律/Snell 定律/薄透镜成像公式实时计算出坐标后,用 SVG 矢量绘制**;LLM 只提供物距/焦距/入射角/折射率等原始物理量(见前文 `opticsScene` 槽),渲染器绝不能把光路交给生图模型去"画"或"猜"——生图模型无法保证像素级角度精确,错误光路必须在架构上被排除,不依赖事后审核。这是本节唯一的"位图完全不能碰"的红线内容。
- **白为主**:材质衬底位图(如有)收在图卡内、面积克制;矢量光路线条与角度标注在近白背景上完成主要视觉表达。

### 运动图像(v-t / s-t)
- **位图部分**:仅限低学段"运动快慢"直觉插画(龟兔赛跑式具象比较图),以及方向甲【运动仪表流】里可选的迷你"运动意图条"图标(小车/人物简笔图标沿路径移动的示意),`stylized-teaching` 档,不含坐标轴或数值。初高中坐标图像本体不使用位图。
- **矢量部分**(核心,全部由数据驱动):坐标轴与刻度、按 `motionGraph` 数据点连线绘制的曲线本体、事件锚点标注胶囊、v-t 图面积阴影(位移)、方向乙【多轨叠合乐谱】的多轨对齐参考线(播放头竖线)——曲线形状必须严格反映数据点,不能用生成位图"画个大概形状"来代替真实函数关系。
- **白为主**:坐标图本身即近白底+曲线强调色,天然贴合;低学段插画图标收在图卡角落或独立小卡内,不铺满整幕。

### 实验装置图(实验设计)
- **位图部分**:实验器材与装置本体——烧杯、铁架台、弹簧测力计、滑轮组、砝码组等,按方向甲要求走**图标化教学插画**风格(`stylized-teaching`,类似 PhET 一类现代科学教育 App 的器材质感,不是旧教材写实素描也不是纯线条图标),近白背景,**图内不含变量标签/读数/引线**,全部由矢量层叠加。
- **矢量部分**:测量点标注气泡+引线(需真连到位,不可断连,呼应 §0.8 精准度打磨的"引线断连"教训)、读数数值标签、自变量/因变量强调色块与视觉动线;方向乙【变量控制看板】的三栏卡片(控制变量/操纵变量/观测变量)、图标+文字、结论横幅——这部分本身是结构化信息设计,走 HTML/矢量,不生成位图。
- **白为主**:方向甲装置位图占画面主体但背景近白;方向乙看板文字占主体、位图退为角落缩略图标,两种排布都不产生深色出血。

### 学科级结论(位图/矢量分工总表)

| 内容类型 | 位图占比 | 位图内容 | 矢量必须精确的内容 |
|---|---|---|---|
| 公式+物理量+单位 | 无 | — | 公式、胶囊标签、推导轨道全部矢量 |
| 受力分析图 | 高(情境铺满卡内) | 斜面/木块/小车/滑轮等写实情境 | 力矢量方向/大小/角度、分类图例、数值胶囊 |
| 电路图 | 低(仅低学段) | 电池/灯泡/开关拟物插画 | 国标元件符号、导线拓扑、通断态 |
| 光路图 | 低(可选材质衬底) | 透镜/镜面/棱镜材质质感 | 光线路径(渲染器几何引擎计算)、角度、成像位置 |
| 运动图像 | 低(仅低学段图标) | 运动意图小图标 | 坐标曲线本体(按数据点连线)、事件锚点 |
| 实验装置图 | 高(装置本体为主) | 器材与装置图标化插画 | 测量点引线、读数标签、变量看板结构 |

> 一句话规律:物理学科里,**"看得见摸得着的实物"越靠位图,"看不见但必须精确的物理量/符号/路径"越靠矢量**;唯一的架构级红线在光路图——光线路径不是审美选择,是可计算的确定性问题,渲染器算、矢量画,位图在这件事上没有发言权。
