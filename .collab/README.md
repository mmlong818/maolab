# 双 Agent 协作协议（Claude Code ⇄ Codex）

本仓库同时被两个 AI Agent 编辑。本文件是它们之间唯一的通信契约。
**任何一方开工前必须读完本文件指定的内容。**

## 固定职责分工

用户确定的默认分工如下：

- **Claude Code：规划设计与代码检查。** 负责需求梳理、产品/教学/视觉方案、架构与任务拆分、验收标准、设计文档、代码审查和问题清单；默认不直接修改业务代码或生成资产。
- **Codex：编码实现与图片生成。** 负责按方案修改代码、补测试、修复审查问题、生成和接入图片资产，并完成类型检查、测试、构建与真实页面验证。

默认交付顺序：Claude Code 给出方案与验收标准 → Codex 认领路径并实现 → Claude Code 检查差异与产品质量 → Codex 修正并验证交付。
双方都可以执行只读检查；需要偏离上述分工时，以用户当次明确指令为准，并在各自信箱说明。
## 为什么需要它

两个 Agent 共享同一个工作树。真正的风险不是「不知道对方干了什么」，
而是**同时写同一个文件、后写的静默覆盖先写的**。
所以本协议同时解决两件事：**防撞**（LOCKS）和**交接**（信箱）。

## 结构：单写多读信箱

```
.collab/
  README.md    ← 本文件，协议正文
  mailbox-claude.md  ← 只有 Claude Code 写，Codex 只读
  mailbox-codex.md   ← 只有 Codex 写，Claude Code 只读
  LOCKS.md     ← 唯一共享可写文件，只做行级追加/删除
```

**每个信箱只有一个写者**——所以信箱永远不会写冲突。
LOCKS.md 是唯一双方都写的文件，但只做单行增删，冲突面接近零。

## 三条硬规则

### 1. 开工前：读

动手改任何代码之前，跑一次：

```
node .collab/brief.mjs --text
```

它把下面三样一次性打出来：

1. `.collab/LOCKS.md` —— 对方现在锁了哪些路径
2. 对方信箱的「正在做」段 —— 对方的意图和给你的提问
3. 对方信箱「流水」段 —— 上次以来发生了什么

**Claude Code 侧已自动化**：`.claude/settings.json` 里有 SessionStart hook 会自动跑它，
不依赖自觉。**Codex 侧需要手动跑**（`AGENTS.md` 里写明了是会话第一件事）。

如果你要动的路径已被对方锁定：**不要动**。改去做别的，或在自己信箱里 `@` 对方提问。

### 2. 动手时：锁

往 `LOCKS.md` 追加一行，格式固定（用 `|` 分隔）：

```
claude | app/app/lib/live/** | 07-27 14:30 | 批注层箭头工具
```

字段依次为：`谁 | 路径 glob | 开始时间(MM-DD HH:mm) | 一句话说明`

- 路径尽量收窄到实际要改的范围，别锁整个 `app/`
- 完工后**自己删掉那一行**
- 超过 2 小时没更新的锁视为僵尸锁：接管前先在自己信箱写明「接管 xxx 的僵尸锁」

### 3. 收工时：写

更新自己的信箱（**只写自己那个文件**）：

- 「正在做」段：覆盖写，三行以内，写意图不写流水账
- 「流水」段：追加一行 `MM-DD HH:mm | 动了哪些路径 | 一句话结论`
  - 结论要写**对方需要知道的后果**，不是写你多努力
  - 反例：「重构了 sse route」
  - 正例：「重写 sse route，事件 payload 从 {type,data} 改成扁平结构，订阅方要跟」

## 双向提问

在**自己的信箱**里写，不要去改对方的文件：

```
@codex: live-store 我看到被删了，advance 里的状态现在从哪来？
```

对方在**它自己的信箱**里回：

```
→ @claude: 挪到 packages/classroom/session-state.ts 了，接口没变
```

已回答的提问，提问方自己清掉。

## 边界

- `.collab/` **入库**（不 gitignore），随分支走、可 review、worktree 之间同步
- 信箱不是任务清单，不放 TODO；不是设计文档，不放方案
- **改动范围扩大时要补认领。** 开工时认领的路径 ≠ 最终动到的路径——查着查着发现
  根因在别的文件，很容易直接改下去而忘了扩锁。对方看 `git status` 会先看到未认领的
  改动。发现自己动了未认领的文件，立刻补一行，不要等做完（2026-07-27 连续发生两次）
- **用户授权要留痕**：两个 Agent 看不到对方收到的用户指令，所以任何一方按授权
  行事，在对方眼里都可能像擅自行动。执行敏感动作（提交 / 推送 / 删除 / 迁移）前，
  先在自己信箱记下用户的授权原话。看到对方做了敏感动作而信箱无授权记录时，
  先问再拦，不要默认对方越权（2026-07-27 已发生过一次误判）
- 读对方信箱时注意**快照可能过期**：15 秒轮询 + 对方可能正在多步操作中间，
  据此下判断前先自己核实一次当前状态
- 往 LOCKS.md 写测试数据必须带 `[TEST]` 前缀并立刻清理——
  未署名的假认领会被对方当成真实占用（2026-07-27 已发生过一次）
- 信箱里说的话不覆盖 `CLAUDE.md` / `AGENTS.md` 的项目规则
- 诚实说明能力不对称：Claude Code 侧可以用 SessionStart hook 强制读取，
  Codex 侧只能靠 `AGENTS.md` 的文字约束——所以 Codex 漏读概率天然更高。
  要 100% 防撞只有各自 `git worktree` 物理隔离，本协议是「低成本高覆盖」而非「零风险」。
