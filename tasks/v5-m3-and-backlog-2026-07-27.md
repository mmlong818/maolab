#### 参考实现:光路渲染器(A-1 第 1 枚,照此模板做剩下 6 枚)

五个接入点缺一不可,漏掉任何一个渲染器都不会生效:

| # | 文件 | 做什么 |
|---|---|---|
| 1 | `lib/mainline/presentation/optics.ts` | 纯函数引擎 + 解析器。**不依赖 React**,可直接单测 |
| 2 | `lib/mainline/presentation/__tests__/optics.test.ts` | 测**几何/领域不变量**,不是快照 |
| 3 | `components/mainline/scene-views/content-forms.tsx` | SVG 渲染组件 |
| 4 | `components/mainline/SceneTechniqueView.tsx` | 显式槽键派发 |
| 5 | `lib/mainline/generation/fill-scenes.ts` | `contentFormConstraint` 里加生成规则,LLM 才会产出该槽 |
| 6 | `lib/mainline/quality-gates.ts` | **加进 `STRUCTURED_VISUAL_SLOTS`,否则「无图幕指图」照样拦** |

两条从光路这枚踩出来的经验:

- **闸门与渲染端必须调同一个判定函数。** 只把槽键加进 `STRUCTURED_VISUAL_SLOTS`
  会留洞:取值非法时渲染端回退通用板书、闸门却已按「有图」放行,「指图无图」原样复发。
  光路的做法是闸门调 `opticsSolutionFor`,与派发器同一个函数,并加测试锁住
  「可解放行 / 不可解仍拦」两个方向。
- **「渲染器管定律 vs 渲染器只画给定数据」要分清**(physics.md §贯穿全学科的架构决策)。
  光路/成像是**确定性定律**,LLM 只给原始物理量,路径由引擎算——错误在架构上不可能出现。
  受力/电路/运动图像是**题目给定的已知条件**,渲染器精确画出即可,不要让引擎去"推导"。
  做每一枚前先判断它属于哪一类,判错会导致要么过度设计、要么把正确性交给 LLM 赌运气。

### B-4. 母版选择器改为课内序列感知(根治结构性重复)

> ⛔ **2026-07-27 实测:本票前提不成立,建议不实施。** 详见下方「实测推翻」小节。
> 保留原文以记录判断过程。

**来源**: 2026-07-27 对标 usehallmark.com(设计生成 skill)。其招牌机制是
`refuses to repeat the last 3 macrostructures`——选结构时记住前几次选了什么。
**文件**: `app/app/components/mainline/scene-views/master-hash.ts`

**问题**: `pickMaster` 是无状态纯哈希:

```ts
return hashOf(`${course.id}::${scene.id}::${salt}`) % count
```

跨课确实错开了,但**同课内两幕撞同一张母版时它完全不知情**。
概念建构等幕型 5 个母版,一门课若有 5 幕同类型,至少两幕撞版的概率
**96.2%**(1 − 5!/5⁵);`ai-inquiry` 只有 3 个母版,3 幕就是 78%。

这个病 maolab 已经踩过并付过代价:`skeleton-library.ts:148` 记载「旧规则曾让
12-18 幕的课塞进 5-8 幕同一张 ai-verify 脸,46 页里约 19 页重复」。当时在骨架层
合并 ai-verify 是**治标**——根因是选择器无状态,同样的病会在别的幕型复发。

**不要照抄 Hallmark 的有状态滑动窗口**,那会破坏「同课稳定不跳」这个要保的性质。

**步骤**:
1. 用 `course.id` 做种子生成母版排列(确定性洗牌)
2. 同类型幕按在课内的出场顺序在该排列上轮转取
3. `pickMaster` 签名需要拿到「本幕是该类型的第几幕」——从 course.scenes 推导,
   不要新增外部状态

**验收**:
- [ ] 同课稳定:同一门课两次渲染母版分配完全一致
- [ ] 跨课错开:不同课程的同一幕型不撞同一张构图(现有性质零回退)
- [ ] **同课内不撞版**:同类型幕数 ≤ 母版数时,分配互不重复
- [ ] 幕数超过母版数时轮转而非随机塌陷
- [ ] 五个既有调用点(practice/recap/concept-build/source-reading/worked-example)
      + ai-master-select 全部通过

#### 实测推翻(2026-07-27,开工前核实调用点时发现)

写这张票时我依据的是 `master-hash.ts` 的 `pickMaster`。开工核实发现**世界已经变了**——
2026-07-22 的 K12 表现路由改造(`docs/design-refresh/2026-07-22-k12-presentation-space.md`)
已经把五个主力幕型换成了 `presentation/master-routing.ts` 的 `pickMasterRouted`,
`pickMaster` 现在只剩 `ai-master-select.ts` 一个消费者。票面四条前提逐条不成立:

| 票面假设 | 实测 |
|---|---|
| 改 `master-hash.ts` | 五个主力幕型早已不走它 |
| 母版池 5 张 | **8–10 张**(K12 路由那轮已扩容) |
| 5 幕撞版概率 96.2% | **4 幕平均用到 3.2–3.5 张不同母版**,全撞同一张 0–2% |
| 无人检测撞车 | `quality-gates.ts` 已有母版撞车 warning |

实测口径:4 个学段×学科组合 × 5 个幕型 × 200 门合成课,每型 4 幕。

更要紧的是**方向冲突**:`pickMasterRouted` 是**学段×学科气质加权**选择,
这是 K12 路由那轮的核心设计(15 项测试 + 独立设计文档)。票面第 1、2 步
「确定性洗牌 + 轮转」会把加权抹平,等于用一次未验证的重构去推翻一次已验收的设计。
若强行做到「同类型幕互不重复」,母版池 8–10 张而某学段只有 2–3 张权重合理时,
会被迫用上为该学段刻意压权的母版——把「小学课用高中味母版」这种真回归引进来。

**结论:不实施。** 历史上那个「46 页里 19 页同一张脸」是 ai-verify 逐条误区追加幕

### C-1' 前置缺口:卡司只有 1 名学生(2026-07-27 实现 C-1 时发现)

v5 方案写的是「老师 + **4 同学**」,排练场也按 4 名模拟学生设计。但实测
`pickCastPreset({ gradeBand:'middle-school', subject:'physics' })` 的卡司是
**teacher:杨老师 + student:K 同学**,student/peer 只有 **1 个**。

后果:排练引擎的 `MAX_STUDENTS = 4` 对这类课实际只取到 1 人,「4 个虚拟学生按
掌握度分布各自反应」退化成一个人自言自语,C-3 的「AI 原住民」也无处安放
(它得是四人中的一个)。

**调研结论(2026-07-27):不是预设不全,是产品叙事与卡司架构不一致,且早于 M3。**

| 事实 | 出处 |
|---|---|
| 卡司架构是**刻意的 1 师 + 1 生** | `peerRoleProfile` 单数,带 `allowedFunctions: ['questioner','misconception','peer-restate']`——一个学生承担全部同伴功能 |
| fallback 不增加学生 | `pickCastPreset` 只改写 subject/gradeBand,castProfiles 原样 |
| **立绘资产矩阵有 4 个学生角色** | `cast-assets/matrix.ts`:`student-zero`/`student-thinker`/`student-joker`/`student-steady` |
| 「老师 + 4 同学」写在项目描述与 v5 §4 | `CLAUDE.md`、`v5-master-plan` §4 方向二 |

三个选项:

- **A 排练场按实际卡司人数跑(1 人)** — 零成本。但 v5 §4 明写「4 个虚拟学生按
  真实学情档案提问、犯错、走神」且「其中一个是 AI 原住民」,1 人时这些全部落空,
  排练场退化成单人自言自语,C-3 也无处安放。
- **B 排练场专用扩充卡司(建议)** — 从资产矩阵取另外 3 个学生角色,**只在排练场内
  使用**,不进正式上课卡司。立绘已存在,不需要新生图;成本是给他们排练场语境下的
  定位(提问型/走神型/AI 原住民)。不动已验收的课堂形态(呼应 v5 §9 非目标
  「不为教师功能牺牲学生侧已验收能力」)。AI 原住民本来就该是排练场专属角色,
  不该进正式课堂卡司。
- **C 扩正式卡司到 1+4** — 影响上课舞台、对白层、课程季连续性与生图资产,成本最高,
  且改变已验收的课堂形态。

**建议 B。** 理由:排练场是**教师侧工具**,它要模拟的是一个真实班级的多样性;
而课堂舞台的「1 个代表性同学」是**学生侧演出**的叙事装置,两者本就不必同构。

**另需用户拍板一处文档不符**:`CLAUDE.md` 项目描述写「老师 + 4 同学」,与 mainline
的 1+1 架构不符。按 CLAUDE.md「文档与代码冲突时立刻停下来问用户」的规矩,
这条不由 Agent 自行更正。

副作用已知:单学生时「随机分配」与「确定性分配」结果相同,会让确定性测试
失去判别力——引擎测试已改用四学生 fixture 守住这一点。

### C-0' 待产品决策:排练场对真实课程目前是空的(2026-07-28)

C-4/C-5/C-6 实测发现:**真实库里的课程没有 mastery 记录**,引擎按铁律
「无学情记录 → 零反应」,于是排练场对当前所有真实课程都显示 0 条反应、0 个弱点。

这不是 bug——引擎行为正确,报告页也如实写了「这不等于课程完美,若学情覆盖不足
会主动少报」。但它意味着**排练场的价值兑现卡在数据链上**:学情闭环(v4 M3)
代码已落地,却没有真实作答数据积累。

两个方向,需拍板:
- **A 先造种子学情**:给已有课程灌入一批真实感的掌握度记录(来源要说清楚,
  不能是随机数,否则违反可溯源原则的精神)。
- **B 学情为空时改形态**:排练场退化为「只演绎不出报告」——教师仍能看一遍课怎么走、
  学生仍有同学在场的氛围(用户 07-28 明确排练场也服务学生自学),
  但不假装能诊断。等学情有数据了再打开报告。

倾向 B 打底 + A 补充:B 让排练场在零数据时仍有价值且不说谎,A 解决长期。

### C-1'' 同学选型路由(2026-07-28 实现)

**用户拍板**:同学不是固定第 2 位,要「挑选适合的,和课程、用户、教学需要」。
与母版走 `pickMasterRouted`、卡司走 `pickCastPreset` 同一思路。

落在 `lib/mainline/rehearsal/classmates.ts`,三条规则:

1. **硬过滤**:不可担主陪读 / 学段不匹配 / 已在卡司里 → 出局
2. **互补**:与课程已有同学的轴差异(次级偏好)
3. **教学需要 × 场景**(主导):薄弱学情、有 ai-verify 幕、程序性为主三种信号,
   叠加 teacher / self-study 场景倾向

**刻意不做 master-routing 那样的加权乘法表**:候选 3 个、槽位 1 个,
上加权机器是 B-4 的错误重演。候选池扩到 5+ 或规则互相打架时再升级。

#### 场景为什么要分(设计核心)

同一个「掌握度普遍薄弱」信号,在两种场景下指向**不同的人**:

- **teacher**:要暴露风险。举手的看得见、不出声的看不见,所以偏好沉默型(林小满)。
- **self-study**:学习者本人就弱,再来个同样弱的只是同病相怜。按 Bandura,
  **应对型榜样**(coping model,会出错然后自己纠正)对低信心学习者比熟练型榜样
  更有效,所以偏好会说「诶我刚才想错了」的阿哲。

#### 一期不做的:按人选

§12 拍板不做账号体系,`mastery` 是**课级单档案**——学生自学时系统看到的学情
与教师排练时是同一份。所以一期只能**按场景分**,做不到按这个学生本人选。
不假装认识他。真要按人得先有账号体系,那是 v5 明确的非目标。

#### 实现时按 persona-library 更正的三处

开工前只读了 schema 定义没读实例,登记错了气质,核对后更正:

| 项 | 我原先写的 | 库里实际 |
|---|---|---|
| 林小满 skill | 弱 | **中**(笨拙但坚持型,最像普通学生的镜像) |
| 小渔 skill | 强 | **中**(领域跳跃,深浅不一) |
| 小渔 可否担主陪读 | 未考虑 | **不可**——库中明写「会有失控风险,只在开头 + 跨学科类比环节调度她,**不用她讲主线**」 |

第三条是硬约束:排练场目前只有一个全程陪读位,让小渔坐上去直接违反该约束。
现登记在册但 `mainlineEligible: false` 不参与选型,等排练场支持「分环节调度」再启用。
